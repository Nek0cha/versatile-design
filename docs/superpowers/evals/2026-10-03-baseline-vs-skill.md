# 比較評価：スキルなし／スキルあり（2026-10-03）

設計書 8章と実装計画 Task 13 に基づく比較評価の記録である。スクリーンショットと生成物はリポジトリに含めず、作業用ディレクトリでのみ扱った。

## 条件

- 生成：お題ごとに、スキルを読ませない生成（baseline）と、`skills/web/SKILL.md` に従う生成（skill）を、それぞれ新しいサブエージェントで行った。モデルは同一である。
- 土台：Vite ＋ React 19 ＋ Tailwind CSS v4 の単一ページ。依存（react-aria-components、motion、gsap、lenis、@iconify/react）は事前に導入した。
- 比較用のスクリーンショット：Web フォントとアイコンが読み込まれた状態で、読み込み後 2.5 秒待ってから、1440px・390px × dark・light の全ページを撮影した。

## お題

1. イラストレーターのポートフォリオサイトを作って。トップページだけでよい
2. 街の小さなカフェのWebサイトを作って。トップページだけでよい
3. 個人開発者向けのサーバー監視ダッシュボードを作って。設定画面も1つ付けて
4. 動画編集ツールの、選択したクリップのパラメータを編集するパネルを作って

## 評価の過程で見つかった点

- `screenshot.mjs` は読み込み直後に撮影するため、登場の動きの途中が写る（お題1・2のスキルあり側が報告）。スクロール連動の演出がある場合、全ページの撮影では未表示の区画が残る。
- 作業環境ではスクリーンショット用のブラウザから Web フォントが読み込まれず、スキルあり側の自己批評は代替の書体で行われた（お題4が報告）。環境の制約であり、スキルの欠陥ではない。
- 文章を生成しない暫定ルールにより、スキルあり側は仮の文章（「ここに〜」）で組まれている。baseline は架空の店名や作品名で埋めているため、見た目の完成度の印象に差が出る。判定時はこの点を考慮する。

## 判定

スキル作者の判定待ちである（合格基準：4つ中4つでスキルありの方が AI 感が薄い）。判定とダメ出しは、受け取りしだいこの節と `anti-patterns.md`・`critique.md` に反映する。
