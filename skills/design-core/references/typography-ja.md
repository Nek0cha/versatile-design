# 和文と欧文の組み合わせ

トークンを決める段階で読む。日本語が中心で英語が混ざる画面のために、和文フォントと欧文フォントの組み合わせを印象ごとに並べる。`user-preferences.md` の「好きなフォント」に指定があれば、そちらを優先する。

ここに載せるフォントは、すべて Google Fonts で配信されている。表のウェイトも配信されていることを確かめてある。

## スキル作者の調整欄

以下は初期値である。スキル作者が実例を見ながら調整する。3節以降の組み合わせ表もスキル作者の調整対象である。`user-preferences.md` とプロンプトの指示が優先される。

| 項目 | 初期値 |
|---|---|
| 印象を決めきれない場合の組 | サイト系は S1、アプリ系は P1 |
| 1つの画面で使う書体の数 | 和文2書体、欧文2書体、等幅1書体まで |
| 1書体あたりに読み込むウェイト | 和文は2つまで、欧文は3つまで |
| 本文の文字サイズ | サイト系 16〜18px、アプリ系 14〜15px |
| 最小の文字サイズ | 12px（注記、ラベル） |
| 本文の1行の長さ | 和文 28〜40字、欧文 60〜75字 |
| 約物の詰め（`palt`） | 見出しだけにかける。本文にはかけない |
| 表にない書体を使う場合の本文の字間・行間 | 和文ゴシック 0.04em／1.8、和文明朝 0.06em／1.9、欧文 0em／1.55 |
| 欧文のサイズ補正 | 既定では補正しない。補正する場合は 90〜110% の範囲 |
| 主役にしない書体 | Noto Sans JP 単独、Inter、Roboto、Poppins、Arial、Helvetica、system-ui（代替として後ろに置くのはよい） |

組み合わせを追加するときは次の手順に従う。

1. 印象を1つ決め、その節の表の末尾に続きの記号（例：S4、P4）で行を足す。記号は振り直さない。報告や `user-preferences.md` から記号で参照されるためである。
2. フォント表と字間・行間の表の両方に行を足す。字間・行間のない組は、モデルが毎回値を推測することになる。
3. 追加する前に、フォント名とウェイトが Google Fonts で配信されていることを確かめる。`https://fonts.googleapis.com/css2?family=<名前の空白を+に置換>:wght@<ウェイト>` が 200 を返せば配信されている。存在しないウェイトは 400 を返す。
4. 主役にしない書体（上の表）を、見出しや本文の先頭に置く組は載せない。

## 1. 選び方

1. コンセプトの「どんな印象を」に最も近い印象を、3節の6つ（静か、精密、遊びがある、力強い、やわらかい、編集的）から1つ選ぶ。
2. その節の表の「合う場面」の列を読み、コンセプトの「誰に」に最も近い組を1つ選ぶ。
3. 2つの印象にまたがる場合は、見出しを主の印象の組から、本文を従の印象の組から取ってよい。ただし調整欄の書体の数を超えない。
4. 選んだ組の記号（例：S1）を、トークンを決めた時点で報告用に控えておく。
5. 「数字」の列に書体がある組で、表、計測値、時刻、コードなど桁を揃えたい場所がある場合は、その等幅書体を使う。等幅書体の用途は、桁を揃える数字、コード、ID に限る。ラベル、小見出し、見出しには使わない（`references/anti-patterns.md` の X17）。「—」の組では、本文の欧文に `font-variant-numeric: tabular-nums` を指定する。この指定はフォントが等幅数字を持たない場合は効かないため、スクリーンショットで桁が揃っているかを確かめる。揃っていなければ、他の組の「数字」の列から1つ借りる。

## 2. 和欧混植の規則

### 2.1 `font-family` の順序

欧文フォントを先に書き、和文フォントを後に書き、最後に総称ファミリーを書く。

```css
:root {
  --font-display: "Instrument Serif", "Shippori Mincho", serif;
  --font-body: "Instrument Sans", "Zen Kaku Gothic New", sans-serif;
  --font-mono: "DM Mono", "Zen Kaku Gothic New", monospace;
}
```

- 理由：和文フォントはほぼすべて欧文の字形も持っている。和文フォントを先に書くと、英字と数字まで和文フォントの欧文で表示され、選んだ欧文フォントが一度も使われない。欧文フォントは仮名と漢字を持たないため、欧文を先に書けば、英字と数字だけが欧文フォントになり、残りは和文フォントに回る。
- 等幅の指定でも、等幅の欧文の後に和文フォントを書く。コードやログに日本語が混ざったとき、中国語の字形で表示されるのを防ぐためである。
- `<html lang="ja">` を必ず指定する。総称ファミリーに落ちたときに日本語の字形が選ばれ、2.4 節の `word-break: auto-phrase` も `lang` が `ja` でないと働かない。
- 部品やページでは、フォント名を直接書かずに上のトークンだけを参照する。

### 2.2 読み込み

- Google Fonts の URL には、表に書いたウェイトだけを指定し、`display=swap` を付ける。和文フォントは配信側で文字ごとに分割されているため、使った文字の分だけ読み込まれるが、ウェイトを1つ増やすごとに読み込みは増える。
- 複数のフォントを1つの URL にまとめた場合、存在しないウェイトを指定したフォントは、エラーにならずに黙って外される。表にないウェイトを足すときは、調整欄の手順3と同じ方法で確かめる。
- 1つのウェイトしかない書体（Dela Gothic One、Mochiy Pop One、Yusei Magic、DotGothic16、Gloock など）に `font-weight: 700` を指定しない。ブラウザが機械的に太らせた字形になる。`font-synthesis: none` を指定し、太らせた字形と傾けた字形が出ないようにする。
- 和文に斜体をかけない。和文には斜体の字形がなく、機械的に傾けた字形になる。強調は太さか書体の切り替えで行う。

### 2.3 欧文のサイズ補正

- 既定では補正しない。表の組は、補正しなくても大きさの差が目立たないものを選んである。
- スクリーンショットで、本文中の英単語や数字が周りの和文より明らかに大きく、または小さく見えるときだけ補正する。確認には「設定 Settings 2026年10月」のような、漢字・英字・数字が並ぶ1行を使う。
- 補正は `@font-face` の `size-adjust` で欧文フォントだけに行う。Google Fonts が返す `@font-face` には手を加えられないため、補正する場合は欧文フォントのファイルを自前で配信し、自分で `@font-face` を書く。

```css
@font-face {
  font-family: "Body Latin";
  src: url("/fonts/instrument-sans.woff2") format("woff2");
  font-weight: 400 700;
  size-adjust: 96%;
}
```

- 補正の幅は調整欄の 90〜110% に収める。この範囲で合わないなら、補正せずに組を変える。
- `font-size-adjust` プロパティは使わない。要素内の和文フォントの大きさまで変わる。
- `size-adjust` のもう1つの使いどころは、読み込み前に表示される代替フォントの大きさを本来のフォントに近づけ、読み込み後のずれを減らすことである。Web での具体的な書き方は媒体別スキルの資料に従う。

### 2.4 約物と改行

- 和文の中の句読点と括弧は全角の文字を使う（、。「」『』（）！？：・）。全角の文字は欧文フォントにないため、和文フォントの字形になる。
- 和文の引用には「」と『』を使う。“ ” と ‘ ’ は欧文フォントの字形になり、幅が狭く位置もずれるため、英文の中だけで使う。
- 三点リーダー（…）とダッシュ（—）は欧文フォントも持っているため、欧文フォントを先に書くと欧文の字形（下に寄った点、細く短い線）になる。ボタンや状態表示の短い文言（「読み込み中…」など）では、そのままでよい。本文で和文の字形が必要な場合（「……」「――」）は、その部分を和文フォントだけを指定した要素で囲む。
- 英字と数字は半角を使う。全角の英数字（Ａ、１）は使わない。利用者が渡した文章に全角英数字があっても、SKILL.md の5節に従って書き換えない。
- 仮の文章では、和文と英単語の間に半角スペースを入れる（例：「Settings を開く」）。数字と単位の間は空けない（例：「2026年」「16px」）。利用者が渡した文章のスペースは足しも引きもしない。対応ブラウザでは `text-autospace: normal` で和欧間に自動でアキが入る。手で入れたスペースのある場所には入らないため、併用してよい。
- 見出しには `font-feature-settings: "palt"` をかけ、約物の前後の空きを詰める。本文にはかけない。字面が詰まり、長い文章が読みにくくなる。BIZ UDPGothic、BIZ UDPMincho、M PLUS 1p のような名前に P の付く書体や、もともと文字幅の詰まった書体では効きが小さい。効いたかはスクリーンショットで確かめる。
- 行頭の括弧の空きは、対応ブラウザでは `text-spacing-trim` で詰まる。見出しの左端が揃わないときに使う。
- 本文には `line-break: strict` を指定し、行頭に小書きの仮名（ゃ、ッ など）や長音記号が来ないようにする。
- 見出しの改行位置は、対応ブラウザでは `word-break: auto-phrase` で文節の切れ目になる。対応していないブラウザのために、2行以上になる見出しでは、改行してよい位置に `<wbr>` を入れるか、文節ごとに `display: inline-block` の要素で囲む。

### 2.5 字間と行間の表の読み方

- 3節の字間・行間の表は、それぞれの組で最初に使う値である。単位は字間が em、行間は文字サイズに対する倍率（`line-height` の単位なしの値）である。
- 「和文」の列は、和文が主になる要素（日本語の見出し、日本語の本文）に使う。英単語が混ざっていても和文の値を使う。
- 「欧文」の列は、英語だけの要素（英語の見出し、英語のラベル、数字だけの表示）に使う。
- 和文見出しの字間は、`palt` をかけた状態の値である。
- 欧文見出しの負の字間は、32px 以上の大きな見出しにだけ使う。それより小さい見出しでは 0 にする。
- 英語の大文字だけの小さなラベル（12〜13px）は、表の値ではなく字間 0.06〜0.1em にする。書体は本文か見出しの書体のままにし、等幅フォントにしない（`references/anti-patterns.md` の X17）。
