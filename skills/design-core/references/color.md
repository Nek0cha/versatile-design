# 色の原則

トークンを決める段階で読む。具体的な数値は末尾の「スキル作者の調整欄」にまとめてある。`user-preferences.md` に色の好みがあれば、そちらを優先する。

色は CSS の `oklch()` で定義する。明度（L）、彩度（C）、色相（H）を別々に調整でき、テーマごとの差し替えで明度だけを動かせるためである。

## 1. アクセントは1色、使う場所を限定する

- UI のアクセントカラーは1色だけ定義する。
- アクセントを使ってよい場所は、次の3つに限る。
  1. 主要な操作（その画面で最も押してほしいボタン1つ、送信、ダウンロードなど）
  2. 選択中の表示（選択中のタブ、選択中の行、フォーカスリング）
  3. 肯定的な状態（ON のスイッチ、完了、接続中など）
- それ以外（見出し、アイコン、飾りの線、背景の面）にアクセントを使わない。見出しを目立たせたいときは太さと明度で行う。
- アクセントが占める面積は、1画面の面積の5%以下を目安にする。少ないほど、使った場所に視線が集まる。
- エラーや警告の色は、アクセントとは別の「状態の色」として定義する。ただし使うのはエラーや警告が実際に起きている場所だけにする。

## 2. 色を足さず、明暗の反転で主役を示す

主役を示すために新しい色を足す前に、明暗の反転で示せないかを先に検討する。

- ダークテーマでは、主要なボタンだけを「明るい面（最も明るいグレー）＋暗い文字」にする。他のボタンは「透明な面＋ 1px の線＋明るい文字」にする。
- ライトテーマでは逆に、主要なボタンだけを「最も暗いグレーの面＋明るい文字」にする。
- この方法を使う場合、アクセントカラーは「選択中」と「肯定的な状態」だけに使い、主要な操作には使わない。どちらの方法を取るかは画面全体で統一する。
- 反転した面は1画面（1つの領域）に1つまでにする。2つ以上あると主役が分からなくなる。

## 3. UI の色と中身の色を分ける場合

次の条件をすべて満たすときに限り、UI のアクセントとは別に「中身の色」の系統を定義してよい（anti-patterns の K2）。

1. 利用者が中身を種類で見分ける必要がある（トラックの種類、カテゴリ、ラベル、グラフの系列など）。
2. 種類を、文字やアイコンだけでは素早く見分けられない。
3. 種類の数が決まっている（目安として8種類以下）。

作り方：

- 中身の色は、明度と彩度を揃え、色相だけを変えて作る。数値は調整欄の表に従う。
- 中身の色には、UI のアクセントと同じ色相（±20度以内）を使わない。選択中の表示と区別できなくなるためである。
- 中身が選択されたときは、中身の色を変えずに、アクセントの枠線（2px）で選択中を示す。
- 色だけに頼らず、ラベルの文字やアイコンも併記する。

## 4. グレーの段階と黒の使い分け

- 背景、面、線、文字は、8〜10段階のグレーで組む。画面の大部分はグレーだけでできているのが正しい状態である。
- 段階は「役割の名前」でトークンにする（調整欄の表を参照）。段階の数字を直接使わず、`surface-1`、`text-muted` のような役割名のクラスを使う。
- グレーには、ごくわずかに色相を持たせる（彩度 0.003〜0.012）。完全な無彩色のグレーより落ち着いて見える。色相は暖色寄り（60〜80度）か、アクセントの色相に寄せる。
- 黒の使い分け：
  - **純粋な黒（`#000`、`oklch(0 0 0)`）**：精密さ、鋭さ、道具らしさを出したいとき（開発者向けツール、写真や映像を主役にする画面）。面の区切りは背景の明度差がほとんど作れないため、1px の線で行う。
  - **暖かみのある黒（明度 0.14〜0.18、彩度 0.004〜0.010、色相 60〜80度）**：長時間読む、会話する、落ち着いた印象を出したいとき。迷ったらこちらを選ぶ。
- ライトテーマの背景も、純粋な白（`#fff`）より、わずかに色相を持たせた白（明度 0.98〜0.99）を基本にする。純粋な白は、写真や作品を主役にする場合に使う。

## 5. ダークとライトでトークンを差し替える構造

- 部品とページは、役割名のトークン（`--color-surface-1`、`--color-text-muted`、`--color-accent` など）だけを参照する。色の値を直接書かない。
- テーマごとの値は1か所にまとめて定義し、テーマの切り替えでは役割名のトークンの値だけを差し替える。部品のコードはテーマを知らない状態にする。
- グレーの段階は役割名で定義し、ダークとライトで明度を逆向きに割り当てる。`surface-0` はどちらのテーマでも最も奥の背景、`text-strong` はどちらのテーマでも最も強い文字である。明度の値は調整欄の表に従う。
- アクセントはテーマごとに明度を調整する。ダークでは明度を上げ、彩度を少し下げる。同じ値をそのまま使うと、ダークでは沈んで見えるか、ぎらついて見える。
- 影はダークではほとんど見えない。ダークで浮いているものを示すときは、影に加えて、面の明度を1段上げるか 1px の線を付ける。
- テーマの指定が片方だけ（「ダークのみ」など）でも、この構造は崩さない。
- コントラストの最低基準：本文の文字と背景は 4.5:1 以上、大きな文字（24px 以上、または 18.66px 以上の太字）と UI 部品の輪郭は 3:1 以上。アクセントの面の上の文字も 4.5:1 以上にする。

## 6. 大胆なアクセントを成立させる条件

彩度の高い色や、面積の大きいアクセント（画面の一部を1色で塗るなど）は、次の条件をすべて満たすときに使ってよい。

1. コンセプトの「どんな印象を」か「何で記憶に残すか」と、その色を結びつける理由を1文で言える。
2. 大きく塗る場所は1画面に1か所だけにし、他の部分はグレーだけで組む。
3. その色の面の上に文字を置く場合、5節のコントラスト基準を満たす。
4. 同じ色を小さな UI（ボタン、選択中）にも使う場合、大きな面と小さな UI が同じ画面で隣り合わないようにする。隣り合うと、どれが押せるものか分からなくなる。
5. ダークとライトの両方で、明度を調整した値を用意する。

## スキル作者の調整欄

以下は初期値である。スキル作者が実例を見ながら調整する。`user-preferences.md` とプロンプトの指示が優先される。

### アクセント

| 項目 | 初期値 |
|---|---|
| アクセントの数 | UI に1色 |
| 1画面での面積の目安 | 5%以下 |
| ダークでの明度 | 0.72〜0.82 |
| ライトでの明度 | 0.50〜0.62 |
| 彩度 | 0.10〜0.18（ダークではライトより 0.01〜0.03 下げる） |
| 選択中の枠線 | 2px |

### グレーの段階（暖かみのある黒を基本にした例）

彩度はすべて 0.004〜0.010、色相は 60〜80度。純粋な黒を基本にする場合は、ダークの `surface-0` を `oklch(0 0 0)` にし、彩度を 0 にする。

| 役割 | 用途 | ダークの明度 | ライトの明度 |
|---|---|---|---|
| `surface-0` | 最も奥の背景 | 0.16 | 0.985 |
| `surface-1` | パネル、カード | 0.19 | 0.965 |
| `surface-2` | 浮いた面、ホバー | 0.23 | 0.94 |
| `surface-3` | 押下中、選択中の面 | 0.27 | 0.91 |
| `line` | 区切り線、入力欄の枠 | 0.32 | 0.87 |
| `line-strong` | 強い区切り、フォーカス前の枠 | 0.42 | 0.78 |
| `text-faint` | 無効、プレースホルダー | 0.55 | 0.62 |
| `text-muted` | 補足、説明、ラベル | 0.70 | 0.48 |
| `text` | 本文 | 0.87 | 0.28 |
| `text-strong` | 見出し、主要な値、反転した主要ボタンの面 | 0.96 | 0.18 |

### 中身の色（K2 の条件を満たす場合のみ）

| 項目 | 初期値 |
|---|---|
| 最大の種類数 | 8 |
| 明度 | ダーク 0.72、ライト 0.60（全種類で揃える） |
| 彩度 | 0.08〜0.12（全種類で揃える） |
| 色相の間隔 | 360度を種類数で割った値を目安にし、アクセントの色相±20度を避ける |

### 状態の色

| 状態 | 色相の目安 | 使う場所 |
|---|---|---|
| エラー | 20〜30度（赤） | エラーの文字、エラーの入力欄の枠 |
| 警告 | 70〜85度（黄〜橙） | 警告の印 |

肯定的な状態はアクセントで示す。成功専用の緑は、アクセントが緑系でない場合でも原則として作らない。
