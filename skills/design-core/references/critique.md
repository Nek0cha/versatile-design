# スクリーンショットによる自己批評

検証の段階で読む。自動チェックの違反がゼロになった後に行う。

## 進め方

1. 媒体別スキルの方法で、PC 幅とスマートフォン幅、対応する全テーマのスクリーンショットを撮る。
2. 撮った画像を実際に見て、C1〜C12 に順に答える。コードを思い出して答えず、画像に写っているものだけで判断する。
3. 不合格の項目を「不合格のとき」に従って直す。直したら自動チェックを再実行し、スクリーンショットを撮り直す。ここまでで1周とする。
4. 2周目も同じ手順で行う。
5. **2周で止め、残った問題は報告する。** 3周目は行わない。周回を重ねるほど無難な方向に収束しやすいためである。報告には、残った項目の番号（例：C4）と、何が問題で、なぜ直しきれなかったかを書く。

スクリーンショットが撮れない環境では、その旨を報告に書き、コードを読み直して各項目を確認する。撮れたことにはしない。

## チェック項目

### C1 コンセプトが画面から読み取れるか

- 問い：コンセプトの3行を知らない人がこの画面を見て、「誰に向けたものか」と「どんな印象か」を言い当てられるか。
- 合格：宣言した形容詞のうち少なくとも2つが、書体・色・余白・写真のどれかから感じ取れる。
- 不合格のとき：印象に最も効く1か所（多くは書体か背景の明度）を変える。装飾を足して印象を作らない。

### C2 記憶のフックが最初の画面にあるか

- 問い：スクロールする前の画面（アプリ系では最もよく使う画面）に、宣言した記憶のフックが見えているか。
- 合格：PC 幅とスマートフォン幅の両方で、フックがスクロールなしに見える。
- 不合格のとき：フックを上へ移すか、大きくする。フックより目立つ要素があれば弱める。

### C3 視線の入口が1つか

- 問い：画面を見た瞬間に最初に目が行く場所はどこか。それは意図した主役か。
- 合格：最初に目が行く場所が1つで、それが主役である。
- 不合格のとき：主役以外の要素の大きさ・太さ・明度を下げる。主役を強めるより、他を弱めるほうを先に試す。

### C4 余白にメリハリがあるか

- 問い：まとまりの中の間隔と、まとまり同士の区切りの間隔に、はっきりした差があるか。
- 合格：区切りの間隔がまとまり内の間隔の2倍以上あり、どこで内容が切り替わるかが線なしでも分かる。
- 不合格のとき：余白の段階のトークンから、まとまり内は狭い値、区切りは広い値を選び直す（anti-patterns の X9）。

### C5 揃えの線が少ないか

- 問い：要素の左端（縦書きなら上端）が、何本の縦の線に揃っているか。
- 合格：揃えの線が少数にまとまっており、意図せず数 px ずれた要素がない。
- 不合格のとき：ずれた要素を最も近い揃えの線に合わせる。線を増やして解決しない。

### C6 アクセントの使用箇所が限定されているか

- 問い：アクセントカラーが使われている場所をすべて指させるか。それは主要な操作・選択中・肯定的な状態のどれかか。
- 合格：アクセントの場所がすべてその3つのどれかであり、1画面での面積が `references/color.md` の調整欄の目安以内である。例外は、`anti-patterns.md` の K3 のずらした影にアクセントを使った場合だけである（`references/color.md` の1節）。
- 不合格のとき：3つ以外の場所のアクセントをグレーに戻す。主役を示す必要があれば、明暗の反転を使う（`references/color.md` の2節）。

### C7 文字の階層が太さと色で作られているか

- 問い：見出し・本文・補足の区別が、サイズの差だけに頼っていないか。
- 合格：同じサイズでも、太さとグレーの段階（`text-strong`、`text`、`text-muted`）の差で階層が読める。一覧の各行が「主（太字・明るい）＋補足（細字・グレー）」のように2段で読める。
- 不合格のとき：サイズの段階を減らし、太さと色の差で区別し直す。

### C8 影は浮いているものにだけ使われているか

- 問い：影が付いている要素をすべて指させるか。それは実際に他の要素の上に浮いているもの（ツールバー、メニュー、ダイアログ、ドラッグ中の要素など）か。
- 合格：ぼかした影（高さの表現）は浮いているものだけにあり、すべて同じ1種類（`--shadow-float`）である。カードや面の区切りは 1px の線か背景の明度差で行われている。ほかに影があるとすれば、`anti-patterns.md` の K3 のぼかさない、ずらした影（装飾。ラベル、バッジ、ボタン、画像だけ、1ページで1つの形）だけである。
- 不合格のとき：浮いていない要素の影を外し、線か明度差に置き換える。K3 の影が浮いていることを示すために使われていたら、外して `--shadow-float` に戻すか、浮いていない要素なら影をなくす。

### C9 スマートフォン幅で崩れていないか

- 問い：スマートフォン幅のスクリーンショットで、はみ出し、重なり、横スクロール、極端に小さい文字、押しにくい小さなボタンがないか。
- 合格：本文が 16px 相当以上、押せる要素が 44px 四方以上の大きさを持ち、横スクロールが発生しない。PC 幅の主役がスマートフォン幅でも主役である。
- 不合格のとき：並びを縦積みに変える、見出しの大きさを幅に応じて縮める、補助的な要素を後ろに回す。

### C10 ダークとライトの両方で破綻していないか

- 問い：対応する全テーマのスクリーンショットで、読めない文字、消えた線、見えない影、浮いたアクセントがないか。
- 合格：どのテーマでも、本文のコントラストが 4.5:1 以上に見え、入力欄など操作できる部品の枠が背景から判別でき（3:1 以上）、面の区切りが判別でき、アクセントの強さが同程度に見える。
- 不合格のとき：色の値を直接直さず、そのテーマのトークンの値を調整する（`references/color.md` の5節）。

### C11 仮の文章と定型コピーの扱いが正しいか

- 問い：利用者が渡していない文章が、媒体別スキルの書き方（web は `../web/references/copy.md`）に従っているか。書けない場所はダミーと分かる形になっているか。定型コピーや架空の実績が入っていないか。
- 合格：書いた文章に、どの商品にも言える言葉や定型の型がない。仮の文章は「ここに見出し」のように一目でダミーと分かる。「Unlock the power of〜」のような定型コピー、架空の数字、架空の推薦文がない。
- 不合格のとき：書き方に従って書き直すか、SKILL.md の5節に従った仮の文章に置き換える。

### C12 禁止リストの自己批評項目に当たらないか

- 問い：`references/anti-patterns.md` のうち「検出：自己批評」とある項目に、画面が当てはまっていないか。
- 確認する項目：X3（角丸カード＋薄い影の3列）、X4（定型的な中央寄せヒーロー）、X6 の後半（絵文字＋形容詞の特徴リスト）、X7（ぼかした光の玉）、X8（ダーク＋ネオンの発光）、X9（均等すぎる余白）、X12（全要素が同じ動き）、X17 のうち lint が拾わないもの（等幅フォントで組んだ小見出しや見出し）、X18（色の点＋状態の文字）、X20（正常な状態のラベル）、K1（ガラス風の半透明）、K2（複数のアクセント）、K3（ぼかさない、ずらした影）、W1（ピル型ラベル）、W2（一律のふわっと表示）、W3（料金表の中央プラン拡大）。
- 状態の表示（X18、X20）は、一覧やダッシュボードで「すべての行に同じ状態の印や文字が並んでいないか」「異常な行が、アイコン＋文字か、データの印の色で一目で見つかるか」を見る。アバターに重ねた在席の点は対象外である。
- X17 と X19 は lint でも検出するが、クラスや CSS の書き方によっては拾えないため、画像でも「等幅の小さなラベル」「端が曲がった片側の色の線」がないかを見る。
- 動きの項目（X12、W2）は静止画では判断できないため、アニメーションのコード（所要時間・遅延・方向の値）を読んで確認する。
- 合格：絶対禁止（X）に当てはまるものがない。条件付き（K）は条件を満たし、理由を報告に書けている。要注意（W）は使う理由を報告に書けている。
- 不合格のとき：該当項目の「代わりにどうするか」に従って直す。
