# 禁止リスト

AI 感を生む定番のパターンを、3段階で管理する。トークンを決める前に一度通読し、実装中と検証時にも参照する。

- **絶対禁止**（X）：使わない。例外はない。
- **条件付き**（K）：機能上の理由を1文で言語化できる場合にだけ使う。
- **要注意**（W）：既定では避ける。使う場合は報告で理由を示す。

各項目の「検出」欄の見方：

- `lint: ルールID` の項目は、媒体別スキルの自動チェックが機械的に検出する。違反がゼロになるまで直す。
- 「自己批評」の項目は機械では検出できない。`references/critique.md` の C12 で、スクリーンショットを見て確認する。

## スキル作者の調整欄

項目を追加するときは次の手順に従う。

1. 3段階のどれに入れるかを決める。迷ったら要注意（W）に入れ、ダメ出しが繰り返されたら絶対禁止（X）へ上げる。
2. 該当する段階の末尾に、続きの番号（例：X17、K3、W4）で見出しを作る。番号は振り直さない。critique.md や報告から番号で参照されるためである。
3. 「禁止事項」「理由」「代わりにどうするか」「検出」の4行を書く。「理由」と「代わりにどうするか」は必ず書く。理由のない禁止はモデルが応用できず、代わりの案がない禁止は別の定番パターンへの置き換えを招く。
4. コードの文字列から機械的に判定できるものは、web スキルの scripts/lib/lint-rules.mjs にルールを追加し、そのルール ID を「検出」に書く。判定できないものは「自己批評」と書く。

## 絶対禁止

### X1 紫〜青のグラデーション背景

- 禁止事項：紫・青・藍・赤紫の範囲だけで作ったグラデーションを背景や大きな面に使う。
- 理由：生成 AI の出力で最も多い配色であり、見た瞬間に「テンプレートから作った」と読まれる。ブランドとも中身とも関係がない。
- 代わりに：背景は `references/color.md` のグレーの段階で作る。面に変化が必要なら、同じ色相の明度差だけで作るか、写真や図版など中身そのものを置く。
- 検出：lint: `purple-blue-gradient`

### X2 グラデーションのかかった文字

- 禁止事項：見出しや数字の文字をグラデーションで塗る（`background-clip: text` とグラデーションの組み合わせ）。
- 理由：定型的に見えるうえ、色が場所ごとに変わるため読みにくく、コントラストも確保しにくい。
- 代わりに：文字は単色にする。強調は太さ、大きさ、書体の切り替え（見出しだけセリフ体にするなど）で付ける。
- 検出：lint: `gradient-text`

### X3 角丸カード＋薄い影の3列配置

- 禁止事項：同じ大きさの角丸カードに薄い影を付け、3列に等間隔で並べる（アイコン＋見出し＋説明文のカードが典型）。
- 理由：特徴紹介の定番の型であり、内容の重みの差が消える。影が「浮いている」という意味を持たない。
- 代わりに：内容に順位を付け、主役の1項目を大きく扱う。並べる場合は大きさや列幅に差を付けるか、カードをやめて罫線と余白だけの一覧にする。面の区切りは影ではなく 1px の線か背景の明度差で行う。
- 検出：自己批評

### X4 定型的な中央寄せヒーロー

- 禁止事項：最初の画面を「中央寄せの大見出し＋サブ文＋ボタン2つ（主要と副次）」だけで構成する。
- 理由：最も多く生成される構図であり、記憶のフックが入る場所がない。
- 代わりに：コンセプトの記憶のフックを最初の画面の主役にする。左寄せ・非対称の配置、画面幅いっぱいの文字、作品や製品そのものを主役にした構図などから、コンセプトに合うものを選ぶ。ボタンは主要な1つに絞る。
- 検出：自己批評

### X5 定番フォントだけで組むこと

- 禁止事項：Inter、Poppins、Roboto、Arial、Helvetica、system-ui など、どこにでもあるフォントだけで文字を組む。
- 理由：何も選ばなかったときの見た目そのものであり、印象を作る最大の手段を捨てることになる。
- 代わりに：コンセプトの印象に合う和文と欧文の組み合わせを `references/typography-ja.md` から選び、フォント指定の先頭に置く。定番フォントは代替として後ろに回すだけにする。
- 検出：lint: `generic-font-only`

### X6 絵文字のアイコン代用と「絵文字＋形容詞」の特徴リスト

- 禁止事項：「🚀 Fast」「✨ Easy」のような絵文字＋形容詞の箇条書きを作る。ボタン、リンク、リスト項目で絵文字をアイコンの代わりに使う。
- 理由：OS ごとに見た目が変わり、色・太さ・大きさを制御できない。形容詞だけの特徴リストは中身がなく、定型コピーの典型である。
- 代わりに：アイコンは SVG のアイコンセット（Web では Iconify）を使い、ラベルと組にする。特徴は具体的な事実で書く。文章がなければ仮の文章を置く（SKILL.md の5節）。
- 検出：lint: `emoji-icon`（形容詞だけの特徴リストは自己批評）

### X7 意味のないぼかした光の玉（blob）の背景

- 禁止事項：強くぼかした色の円や不定形を背景に浮かべる。
- 理由：何も表していない装飾であり、空いた場所を埋めるための定番の手段になっている。
- 代わりに：余白を余白のまま残す。背景に何か置くなら、中身と関係のあるもの（作品の一部の拡大、図版、文字そのもの）にする。
- 検出：自己批評

### X8 ダークモード＋ネオンの発光

- 禁止事項：暗い背景の上で、彩度の高い色の文字や線に発光の効果（色付きの `text-shadow`、`box-shadow`、`drop-shadow` のにじみ）を付ける。
- 理由：「ダーク＝近未来」という連想に頼った定番であり、にじみで文字の輪郭がぼやけて読みにくい。
- 代わりに：ダークでは明度の差で階層を作る。アクセントはにじませず、面積を絞って塗る（`references/color.md` の1節）。
- 検出：自己批評

### X9 均等すぎる余白

- 禁止事項：要素間の間隔を、関係の強弱に関係なくすべて同じ値（例：どこも 24px）にする。
- 理由：どこがまとまりでどこが区切りかが読めず、情報の構造が消える。リズムのない画面は平均的に見える。
- 代わりに：余白の段階をトークンで定義し、関係の近い要素は狭く、区切りは広くする。区切りの間隔は、まとまり内の間隔の2倍以上にする。
- 検出：自己批評

### X10 ボタンやリンクの文字の矢印

- 禁止事項：ボタンやリンクの中に `→` `↗` `›` `»` `▼` などの文字の矢印を入れる。
- 理由：フォントによって太さや縦位置がずれ、サイズ・色・動きを細かく制御できない。
- 代わりに：SVG のアイコン（Web では Iconify）を使い、文字との間隔と縦位置をトークンで揃える。
- 検出：lint: `text-arrow`

### X11 Tailwind 標準パレットのクラスを直接使うこと

- 禁止事項：`bg-indigo-500`、`text-slate-400` のような標準パレットのクラスを書く。
- 理由：標準パレットの色は誰が使っても同じになり、AI 感の主な発生源である。テーマの差し替えもできない。
- 代わりに：色はすべて自前のトークンとして定義し（`references/color.md`）、`bg-surface-1` や `text-muted` のようなトークン名のクラスを使う。
- 検出：lint: `tailwind-default-palette`

### X12 全要素が同じ速さ・方向・遅延で動くこと

- 禁止事項：画面上のすべての要素を、同じ所要時間・同じ方向・同じ遅延で表示させる。
- 理由：動きに意味の差がなくなり、機械的に見える。
- 代わりに：主役だけを先に、または大きく動かし、補助的な要素は短く小さく動かす。方向は要素の役割に合わせる。数値は媒体別スキルの資料に従う。
- 検出：自己批評

### X13 既定のイージングとイージングの指定漏れ

- 禁止事項：`ease`、`linear`、`ease-in-out` などブラウザ既定のイージングを理由なく使う。イージングを指定しない。
- 理由：動きの終わり方が機械的になり、どの画面でも同じ手触りになる。
- 代わりに：用途別のイージング（登場、退場、操作への反応など）を `cubic-bezier` でトークンとして定義し、それを使う。
- 検出：lint: `default-easing`

### X14 すべてのプロパティを対象にした transition

- 禁止事項：`transition: all`（Tailwind では `transition-all`）を使う。
- 理由：意図しないプロパティまで動き、描画も重くなる。
- 代わりに：動かすプロパティ（`transform`、`opacity`、`background-color` など）を明示する。
- 検出：lint: `transition-all`

### X15 動きを減らす設定への未対応

- 禁止事項：アニメーションを使いながら、利用者の「視差効果を減らす」設定（`prefers-reduced-motion`）に対応しない。
- 理由：動きで体調を崩す利用者がいる。アクセシビリティの必須事項である。
- 代わりに：動きを減らす設定のときは、移動や拡大をやめ、短い不透明度の変化だけにするか、動きをなくす。
- 検出：lint: `no-reduced-motion`

### X16 ブラウザ標準のままの選択欄と数値入力

- 禁止事項：見た目を整えていない `<select>` や `<input type="number">` を使う。
- 理由：OS とブラウザごとに見た目が変わり、開いた一覧や増減ボタンのデザインを制御できない。数値入力はホイール操作で値が変わる事故も起きる。
- 代わりに：アクセシビリティに対応した部品（Web では React Aria Components）で作り、見た目はトークンで整える。
- 検出：lint: `native-select`、`native-number-input`

## 条件付き

使う場合は、機能上の理由を1文で言語化し、報告に書く。lint に検出される使い方をする場合は、直前の行に次の形式の抑制コメントを書く。理由のない抑制コメントはそれ自体が違反になる。

```
design-lint-disable-next-line <ルールID> -- <理由>
```

### K1 ガラス風の半透明（glassmorphism）

- 禁止事項：装飾目的で、背景をぼかした半透明の面を使う。
- 使ってよい条件：写真、動画、地図、キャンバスなど情報量の多いものの上に操作パネルを重ね、下の中身を見せ続ける必要がある場合に限る。
- 理由：半透明は「下に何かがある」ことを伝える機能を持つ。下が単色の背景なら機能がなく、定番の装飾にしかならない。
- 代わりに：条件に当たらない場合は、不透明な面を背景の明度差で区切る。
- 検出：自己批評

### K2 複数のアクセントカラー

- 禁止事項：操作や状態を示す色を2色以上にする。
- 使ってよい条件：UI の色（操作・選択中・状態）と、中身の色（トラックの種類、カテゴリ、グラフの系列など）を分けて定義する場合に限る。UI の色は1色のままにする。
- 理由：アクセントが複数あると、どれが押せるものか、どれが選択中かが読めなくなる。中身の区別のための色は役割が違うため、別の系統として扱える。
- 代わりに：条件の詳細と色の作り方は `references/color.md` の3節に従う。
- 検出：自己批評

## 要注意

使う場合は、なぜそれがこの画面に必要かを報告に書く。

### W1 見出しの上の小さいピル型ラベル

- 禁止事項：見出しの上に「New」「Beta」「Introducing」などの小さな角丸ラベルを置く。
- 理由：LP の定番の型であり、多くの場合は中身のない飾りになっている。
- 代わりに：本当に新しい情報なら、見出しや本文の中で具体的に書く。区分を示したいなら、字間を広げた小さな文字など、ピル以外の方法を検討する。
- 検出：自己批評

### W2 一律のふわっと表示

- 禁止事項：スクロールで現れる要素すべてに、下から少し浮き上がりながら現れる同じ動きを付ける。
- 理由：どの画面にもある定番の動きで、見せ場が生まれない。全要素が同じ速さ・方向・遅延になる場合は X12 として絶対禁止である。
- 代わりに：動きを付ける場所を記憶のフックと主役に絞る。それ以外は動かさないか、ごく短くする。
- 検出：自己批評

### W3 料金表の中央プラン拡大と「Most Popular」バッジ

- 禁止事項：3つ並んだ料金プランのうち中央だけを拡大し、「Most Popular」「おすすめ」のバッジを付ける。
- 理由：料金表の定番の型で、テンプレートの印象を強く与える。
- 代わりに：プランの差を比較しやすい表にし、推す理由がある場合は具体的な理由（「5人以上のチームはこちら」など）を書く。
- 検出：自己批評
