# 自作の角丸（squircle）と、フォントを使わない文字

手順4で、ボタンや枠の形を `border-radius` の円弧ではない角丸（squircle）にする場合と、ロゴや名前をフォントを使わずに図形で組む場合に読む。

## 1. squircle

辺から角へ曲率が連続してつながる角丸である。Figma の「角の滑らかさ（corner smoothing）」と同じ考え方で、`border-radius` の円弧より柔らかく見える。

### 1.1 描き方

- CSS の `corner-shape: squircle` は Chromium 系でしか動かないため、使わない。SVG のパスで描く。
- `(幅, 高さ, 半径, smoothing)` からパスを返す関数を自作する。ライブラリは入れない（数十行で書け、形の変化をアニメーションさせるときに値を直接扱えるため）。

```ts
const f = (v: number) => String(Number(v.toFixed(2)));

// smoothing（0〜1）を上げるほど、角の曲線が辺の内側から始まり、四角に近い滑らかな形になる
export function squirclePath(w: number, h: number, radius: number, smoothing: number): string {
  const s = Math.min(1, Math.max(0, smoothing || 0));
  const half = Math.max(0, Math.min(w, h) / 2);
  const r = Math.min(Math.max(radius, 0), half);
  const p = Math.min(r * (1 + s), half); // 角の曲線が辺の上で始まる位置
  const k = p * (0.5523 + 0.3 * s); // ベジェの制御点までの長さ
  return [
    `M${f(p)},0`, `L${f(w - p)},0`, `C${f(w - p + k)},0 ${f(w)},${f(p - k)} ${f(w)},${f(p)}`,
    `L${f(w)},${f(h - p)}`, `C${f(w)},${f(h - p + k)} ${f(w - p + k)},${f(h)} ${f(w - p)},${f(h)}`,
    `L${f(p)},${f(h)}`, `C${f(p - k)},${f(h)} 0,${f(h - p + k)} 0,${f(h - p)}`,
    `L0,${f(p)}`, `C0,${f(p - k)} ${f(p - k)},0 ${f(p)},0`, 'Z',
  ].join(' ');
}
```

- テストで押さえること：smoothing 0 で `M半径,0` から始まる。半径が短辺の半分を超えても、幅や高さが 0 でも、NaN を含まず、x は幅以下・y は高さ以下に収まる。
- 画像や面を squircle で切り抜く場合は、同じパスを SVG にして `mask-image` に渡す（`data:image/svg+xml,` に `encodeURIComponent` したもの）。

### 1.2 ボタンの背景にする

- ボタンの中に `position: absolute; inset: 0` の SVG を置き、上の関数で作ったパスを描く。
- ボタンの寸法は、`ResizeObserver` の通知を受けたときに `offsetWidth` と `offsetHeight` で測る。`contentRect` は padding を含まないため、背景が潰れる。`borderBoxSize` も環境によって padding を含まない値が返ることがある。
- `transform: scale()` で拡大しても `offsetWidth` は変わらないため、拡大の動きで形を描き直す必要はない。
- 形の変化と大きさの変化を動かす場合は、`references/motion-web.md` の「1つの部品に2つのばね」に従う。

### 1.3 モチーフの拾い方

squircle にする理由を、題材の中から拾う。利用者が渡した写真や素材に、すでにその形があることが多い（例：機内の窓、ブラウン管、スマートフォンの画面、錠剤の包装）。拾った形は、覗き窓、ボタン、画像の切り抜き、ファビコンのように、同じ画面の中で繰り返し使う。1か所だけの squircle は、気まぐれな角丸に見える。

## 2. フォントを使わない文字（ロゴ、名前）

### 2.1 字形の作り方

- 題材の世界に、文字を作る規則がすでにあればそれを借りる（例：視力検査表の視標文字は 5×5 のグリッドで、線の太さが文字の高さの 1/5）。規則のない手描き風の文字は、整然とした画面の中で浮く。
- 字形は小さなグリッドの座標で定義し、単位の大きさを掛けて配置する。文字の幅、文字間、高さは単位の整数倍にする。
- 斜めの線は、向かい合う辺を平行にして、太さを一定にする。片側だけ傾けたくさび形にしない。

### 2.2 1文字を1本の輪郭で描く

- 縦線・腕・脚のような部品を、重なった複数の図形で描かない。1文字（穴のある文字は外側と内側の輪郭の組）を、重なりのない1本の輪郭にする。
  - 重ねると、輪郭を線で描いていく演出（`stroke-dashoffset` など）のときに、部品の内側に線が見える。
  - 1本のパスにまとめて `fill-rule="evenodd"` で塗ると、重なった部分が穴になる。
- 斜めの部品どうしの交わり（K の腕と脚など）は、交点を計算して輪郭の頂点にする。片方の部品の根本を、もう片方の中に埋めて隠さない。
- テストで押さえること：文字ごとの図形の数、向かい合う辺の傾きが等しいこと、未対応の文字で例外を投げること。

### 2.3 置き方

- `<svg role="img" aria-label="名前">` にし、中の `<path>` は読み上げさせない。
- 画面幅で単位の大きさを変える場合は、640px 未満で小さくする。
- 読み込み時に輪郭を描いてから塗る演出をする場合は、`prefers-reduced-motion: reduce` のときに塗った状態で表示する。
