# 見やすくする

「見やすくして」「整理して」「ごちゃごちゃしている」のように、画面が読み取りにくい、探しにくいという依頼で読む。進め方と守る範囲は `references/refine.md` に従う。

## 目指すこと

- 画面を開いた瞬間に、最初に見る場所が1つに決まる。
- 探している項目や操作が、読み進めずに位置で見つかる。
- 文字を足して分からせるのではなく、まとまりと並びで分からせる。

## 見る点

直す前のスクリーンショットで、次を確かめる。

1. 最初に目が行く場所が1つで、それが主役か。主要の見た目のボタンが2つ以上ないか（`../design-core/references/critique.md` の C3、`references/intuitive-ui.md` の5.1節）。
2. 関係する項目どうしが近く、関係しない項目との間が広いか。すべてが同じ間隔で並んでいないか（C4、`../design-core/references/anti-patterns.md` の X9）。
3. 配置や見出しで分かることを言い直している説明文や補足のラベルがないか。同じ情報が2か所に出ていないか。すべての行に正常な状態のラベルが付いていないか（W4、X20）。
4. 文字の階層が、太さとグレーの段階で3段ほどに収まっているか。サイズの段階が多すぎないか（C7）。
5. 要素の左端が少数の線に揃っているか（C5）。
6. 使う頻度の低い操作や高度な設定が、常に全部見えていないか（`references/intuitive-ui.md` の6節）。
7. 区切りのための枠、線、影、背景の面が重なっていないか（囲みの中に囲みがある、など）。

## 直し方

効果の大きい順に行う。1つ直すごとに全体を見直す必要はなく、まとめて直してから検証する。

1. **減らす**：3と7で見つけたものを消す。消してよいか迷ったら、消した状態で意味が通るかを考え、通るなら消す。消した説明文は報告に書く。
2. **まとめる**：関係する項目を見出しの下に集め、まとまりの中の間隔を狭く、まとまりどうしの間隔をその2倍以上にする（余白の段階のトークンから選ぶ）。まとまりを枠で囲むのではなく、余白と 1px の線か背景の明度差で区切る。
3. **並べ替える**：よく使うものと重要なものを、読み始めの位置（左上、まとまりの先頭）に移す（`references/intuitive-ui.md` の5.2節）。高度な設定は、開いたときだけ見えるようにする（6.1節）。行ごとの操作は、ホバーか選択のときに出す（6.2節、`references/components/states.md`）。
4. **主役を決める**：主役以外の大きさ、太さ、明度を下げる。主役を強めるより、ほかを弱めるほうを先に試す（C3）。
5. **階層を整える**：サイズの段階を減らし、太さとグレーの段階（`text-strong`、`text`、`text-muted`）で区別し直す（C7）。
6. **揃える**：ずれた要素を最も近い揃えの線に合わせる（C5）。

### 設定画面の場合

- 1つの設定を「ラベル（と必要なら1行の補足）＋現在の値＋操作」の1行にし、同じ用途の行の高さを揃える（`references/mode-app.md` の3.1節）。
- 補足は、その設定だけが持つ判断の材料（影響の範囲、元に戻せるか、単位）があるときだけ書く。
- 削除や初期化などの危険な設定は、末尾にまとめて離す（`references/intuitive-ui.md` の7.1節）。
- 保存の方法（その場で反映か、保存のボタンか）を画面の中で統一する。

## やってはいけないこと

- 文字を全体的に大きくする、余白を一律に広げる。メリハリが消え、かえって読みにくくなる（X9）。
- 区切るためにカードで囲み直す、影を足す（X3、C8）。
- 分かりにくさを、説明文やツールチップを足して補う。先に並びと見出しを直す（W4）。
- ボタンや設定を消す。隠すのはよいが、消したいものは報告で提案する。

## 確かめ方

- 直す前と後のスクリーンショットを並べ、最初に目が行く場所が後のほうで1つになっているか。
- 依頼の画面でよく行う操作を1つ選び、その操作の場所を、画像を見てすぐに指させるか。
- `references/intuitive-ui.md` の「実装の後の確かめ方」の1、6、9。
