# 仕上げる

「仕上げて」「細かいところを整えて」「リリース前に見直して」「いい感じにして」のように、全体の方向は変えずに細部の質を上げる依頼で読む。目的が決めきれない依頼もこの手順書で扱う。進め方と守る範囲は `references/refine.md` に従う。

## 目指すこと

- 構図と系統はそのままに、作りかけに見える場所、ずれている場所、抜けている状態をなくす。

## 見る点

次の一覧を順に点検する。当たったものを `references/refine.md` の4節の手順3の書き出しに加える。

1. **自動チェック**：違反が残っていないか。
2. **揃えと余白**：数 px ずれた要素がないか（`../design-core/references/critique.md` の C5）。余白の段階のトークン以外の値（`p-[13px]` のような任意の値）がないか。
3. **部品の状態**：操作できるすべての部品に、ホバー、押下、フォーカス、無効の見た目があるか（`references/components/states.md`）。
4. **ずれ**：ボタンの押下や読み込み中で幅が変わらないか。エラーや説明が出たときに下の部品が動かないか。スクロールバーが出たときに中身がずれないか。読み込みが終わったときに部品が跳ねないか（C13、`../design-core/references/anti-patterns.md` の X23〜X26）。
5. **抜けている状態**：すぐ表示できない画面と領域に読み込みの表示があるか。空のとき、エラーのときの表示があるか（X24、`references/components/loading.md`、`references/components/states.md`）。
6. **文字**：見出しの最後の行が1〜2文字だけになっていないか。数字の桁が揃っているか（`tabular-nums`）。和文と欧文の組み方が `../design-core/references/typography-ja.md` に沿っているか。
7. **説明**：配置で分かることを言い直している説明文やラベルがないか（W4）。
8. **幅とテーマ**：スマートフォン幅と、対応するすべてのテーマで崩れていないか（C9、C10）。
9. **ファビコンと `<title>`**：雛形のままになっていないか（X21）。
10. **動き**：所要時間とイージングがトークンどおりか。動きを減らす設定に対応しているか（`references/motion-web.md`）。

## 直し方

- 目立つ順に直す。最初の画面、主要な操作、よく使う部品の順である。
- 新しい要素を足さない。足すのは、5の抜けている状態の表示だけである。
- 4のずれは、`references/intuitive-ui.md` の3.2節の「Web での実装」に従って、場所を最初から確保する方法で直す。

## やってはいけないこと

- 仕上げの名目で、構図、配色、書体を変える。印象を変えたいなら「印象を強くする」か「落ち着かせる」の依頼として扱う。
- 一覧の点検を省いて、目に付いた所だけを直す。

## 確かめ方

- 上の一覧の10項目すべてについて、直した後に当てはまるものがないか。当てはまるものが残った場合は報告に書く。
- 4は、変わる前と後の状態を撮って比べる（C13）。
