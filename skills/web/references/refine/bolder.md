# 印象を強くする

「地味」「物足りない」「印象に残らない」「ありがちな見た目」のように、画面に特徴がないという依頼で読む。進め方と守る範囲は `references/refine.md` に従う。

## 目指すこと

- 画面を見た人が「何で覚えたか」を1つ言えるようにする。
- 派手にするのではなく、差を付ける。大きいものと小さいもの、明るい面と暗い面、動くものと動かないものの差である。

## 見る点

1. 記憶のフック（`../design-core/references/concept-brief.md` の1節）があるか。あるなら最初の画面に見えているか（`../design-core/references/critique.md` の C2）。
2. 主役と脇役の大きさの差が小さく、すべてが同じ強さに見えていないか（C3）。
3. 書体が定番のフォントだけになっていないか（`../design-core/references/anti-patterns.md` の X5）。見出しと本文が同じ書体、同じ太さになっていないか。
4. 画面全体が同じ明度の面だけでできていて、平坦になっていないか。
5. 定型の構図（中央寄せの見出しとボタン2つ、3列のカード）になっていないか（X4、X3）。
6. 写真、製品、作品など、中身そのものが脇に追いやられていないか。

## 直し方

上から順に1つずつ試し、印象が変わったところで止める。全部を同時に行わない。

1. **主役を決めて差を広げる**：主役を1つ決め、ほかとの大きさの差を広げる。サイト系では見出しと本文の大きさの比を、`references/mode-site.md` の調整欄の範囲の上のほうに寄せる。
2. **書体**：見出しに性格のある書体を当てる。和文と欧文の組は `../design-core/references/typography-ja.md` から、今の印象に合うものを選ぶ。
3. **明暗**：面を1つ、明暗を反転させて主役にする（`../design-core/references/color.md` の2節）。
4. **構図**：左寄せ・非対称の配置、画面幅いっぱいの文字、中身（写真、製品、作品）を大きく扱う構図などに組み替える（X4 の「代わりに」）。
5. **記憶のフックを足す**：1で見つからなかった場合に限り、`concept-brief.md` の1節の考え方でフックを1つ決めて足す。足したフックは報告に書く。

### アプリ系の場合

アプリ系は大きな文字や演出で印象を作らない（`references/mode-app.md` の1節）。見せ場は部品の作り込みと状態の伝え方にある。反転した主要ボタンの形、空状態の見出しだけに使う書体、数値入力の手触り、起動時の読み込み画面などから1つを選んで作り込む。

## やってはいけないこと

- 色を増やす。アクセントは1色のままにする（K2）。
- グラデーション、発光、ぼかした光の玉で派手にする（X1、X7、X8）。
- すべての要素を大きく、太くする。差がなくなり、結局また平坦になる。
- すべての要素に入場の動きを付ける（X12、W2）。
- 今の系統（色や書体）を総入れ替えする。それは作り直しであり、`references/refine.md` の1節に従って新規として扱う。

## 確かめ方

- 直した後の画面について、「この画面は〜で覚える」を1文で言えるか。直す前には言えなかったか。
- C1、C2、C3。
