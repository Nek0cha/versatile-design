# 幅に合わせる

「スマホで崩れる」「狭い画面で見づらい」「タブレットでも使えるように」のように、画面の幅による崩れを直す依頼で読む。進め方と守る範囲は `references/refine.md` に従う。

## 目指すこと

- どの幅でも、はみ出し、重なり、横スクロールがなく、PC 幅の主役がほかの幅でも主役である。

## 見る点

SKILL.md の 5.2 の撮影で、この依頼に限り幅を足して撮る：`--widths 1440,1024,768,390`。中間の幅でだけ崩れることが多いためである。

1. 横スクロール、はみ出し、要素の重なりがないか（`../design-core/references/critique.md` の C9）。
2. 本文が 16px 相当以上、押せる要素が 44px 四方以上あるか（C9）。
3. PC 幅の主役が、狭い幅でも最初の画面に見えているか（C2）。
4. 表、ツールバー、サイドバー、長い見出し、横に並んだボタンの扱い。
5. ホバーでしか出ない操作が、タッチの画面でも使えるか（`references/components/states.md`）。
6. 固定の幅（`w-[480px]` など）や固定の高さが、狭い幅で中身を切っていないか。

## 直し方

- **並び**：横に並んだまとまりを、狭い幅で縦に積む。積む順番は、重要なものを上にする。
- **サイドバー**：狭い幅では、開閉できる引き出しにする。開閉の操作は左上の決まった位置に置く。
- **表**：必要な列だけを残し、残りは行を開いたときに見せる。列を減らせない表は、表だけを横にスクロールする領域にする。ページ全体を横にスクロールさせない。
- **見出し**：大きさを幅に応じて縮める（`clamp()`）。単語の途中で改行しないようにする。
- **ボタン**：横に並んだボタンは、狭い幅で主要なボタンを全幅にし、副次のボタンを下に置く。
- **固定の値**：固定の幅は `max-w` に、固定の高さは `min-h` に置き換える。
- **ホバーだけの操作**：タッチの画面では常に表示するか、行を押したときに出す。

## やってはいけないこと

- 狭い幅で情報や操作を消す。順番を後ろに回すか、開いたときに見せる。
- 文字を小さくして詰め込む。本文は 16px 相当より小さくしない。
- 幅ごとに別の部品を作り、見た目や振る舞いを変える。同じ部品の並びを変える（`references/intuitive-ui.md` の3.1節）。

## 確かめ方

- 4つの幅のスクリーンショットすべてで、C9 に合格するか。
- 4つの幅で、主役が同じ要素か。
