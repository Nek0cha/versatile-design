# サイト系の原則と数値

コンセプトでサイト系（ポートフォリオ、企業サイト、LP など）と判定した画面で、トークンを決める段階で読む。具体的な数値は末尾の「スキル作者の調整欄」にまとめてある。

- このファイルは、`../design-core/references/color.md` と `../design-core/references/typography-ja.md` の原則に、サイト系で特に効く判断を足すものである。両者と重なる数値はそちらに従う。例外は、調整欄の表で「サイト系での上書き」と明記した行だけであり、その行に書いた条件を満たす場合に限ってサイト系の値を使う。条件を満たさなければ、両者の値に戻る。
- `../design-core/references/anti-patterns.md` の禁止事項は、このファイルより優先する。実例で見られた手法でも、禁止事項に当たるものは使わない。
- 数値の幅は、スキル作者が選んだ実例4件の観察（`references/observations/site.md`）から、複数のサイトにまたがる傾向として取り出したものである。特定のサイトを再現するための値ではない。

## 1. サイト系の目的

- サイト系の目的は、記憶に残ることと、世界観を伝えることである。迷わず操作できることは前提として満たしたうえで、印象を優先する。
- 見せ場は、大胆なタイポグラフィ、余白、スクロールの演出の3つである。この3つのどれで記憶のフックを作るかを、コンセプトの段階で決める。

## 2. 記憶のフックは1つに絞る

- 観察した実例は、どれも見せ場を1つだけ持ち、ほかの部分は整然と組んでいた。見せ場を2つ以上にすると、どれも印象に残らない。
- 記憶のフック（`../design-core/references/concept-brief.md` の1節）を最初の画面の主役にし、最初の画面のほかの要素は小さくして画面の四隅や端に寄せる。
- フックの作り方の型として、次のようなものがある。どれを選ぶか、どう具体化するかはコンセプトから決め、型をそのまま当てはめない。
  - 画面に収まらない大きさの文字を1つ置き、はみ出させる。
  - 作品や製品を1つずつ、大きな余白の中に置く。
  - 意味を持たせた色の帯や手描きの線など、サイト全体で繰り返す1つの記号を作る。
  - スクロールの方向や速さを変える演出を1つだけ入れる。
- フック以外の部分では、新しい装飾や演出を足さない。フックが目立つのは、ほかが静かだからである。

## 3. 文字

### 3.1 サイズの差を大きく取る

- 最大の文字（ヒーローの見出しなど）は、本文の4〜9倍にする。差が小さいと、サイト系の見せ場であるタイポグラフィが生まれない。
- 最大の文字の大きさは画面幅に合わせて伸縮させ、PC 幅で画面幅の4〜14%に収める。CSS では `clamp()` で最小値と最大値を決める。
- 大きな見出しを置く場合も、見出しの段階は3〜4段に絞る。中間のサイズを増やすと差が薄まる。

### 3.2 大きな欧文見出しの字間と行間

大きさと太さによって、字間を詰めるか広げるかの方向が逆になる。

- **巨大な太字（PC 幅で 80px 以上）**：字間を 0 からマイナスへ詰め、複数行にする場合は行間を 1.0 以下にして、文字を1つの塊として見せる。大きな文字は字間と行間が開いて見えるためである。
- **中くらいの大文字見出し、小さなラベル**：字間を広げる。大文字だけの語は、字間を広げないと詰まって読みにくい。書体は本文か見出しの書体のままにし、等幅フォントにしない。等幅の大文字ラベル（「TODAY'S MENU」のようなもの）は AI が作った画面の定番の見た目である（`../design-core/references/anti-patterns.md` の X17）。
- 数値は調整欄の表に従う。和文の見出しの字間と行間は `../design-core/references/typography-ja.md` に従う。

### 3.3 書体の役割を分ける

- 書体は `../design-core/references/typography-ja.md` の組から選び、2〜3書体に絞る。
- サンセリフとセリフ体を組み合わせる場合は、役割で分ける（見出しと補足、あるいは1つの見出しの中で行ごとに切り替えるなど）。役割の決まっていない混在はしない。
- 英字の大文字見出しに和文の小さな訳語を添える形は、和文中心のサイトで見出しの形を統一する方法として使える。この場合、訳語は本文より小さく、太さで区別する。

### 3.4 小さい文字と和文の本文

- 12〜13px の小さい文字（ラベル、注記、肩書き）は字間を広げる。小さい文字は字間が詰まって見えるためである。値は `../design-core/references/typography-ja.md` に従う（英語の大文字だけのラベルは 0.06〜0.1em）。観察した実例の値（0.05〜0.12em）もほぼこの範囲に収まる。
- 和文の本文の行間は、観察した実例でも 1.6〜2.1 と広かった。初期値は `../design-core/references/typography-ja.md` の調整欄に従い、段落の幅を短めにする場合は行間を範囲の下側に寄せてよい。

## 4. 色

色の作り方は `../design-core/references/color.md` に従う。サイト系では次の点を加える。

- UI のアクセントは0〜1色にする。作品や写真が主役のサイトでは、アクセントを持たず、UI を背景と文字のグレーだけで組む方法を先に検討する。UI の色は作品の色と競合するためである。
- アクセントを使う場所は、次の2つの型のどちらかに統一する。
  1. **一点**：ロゴの印、主要なボタン、小さな印など、面積の小さい場所だけ。
  2. **意味を持った帯や面**：「ここが大事」のような1つの意味だけを持たせ、その意味の場所にだけ使う。`../design-core/references/color.md` の6節の条件を満たすこと。
- サイト系では、`../design-core/references/color.md` の6節の条件をすべて満たす場合に限り、アクセントの彩度を `../design-core/references/color.md` の上限（0.18）を超えて、調整欄の表の値まで上げてよい（サイト系での上書き）。明度の高い強い色（黄、黄緑など）は、文字の色には使わず、面として塗ってその上に暗い文字を置く。
- 背景は、わずかに色相を持たせた白か、黒に近い暗色にする。明度と彩度は `../design-core/references/color.md` の調整欄の値を基本にする。紙のような温度を出したい場合に限り、ライトの背景を一段暗いオフホワイトにしてよい。その場合はグレーの段階全体を調整欄の「オフホワイトの段階」に差し替え、`surface-0` だけを変えない（`surface-1` が背景より明るくなり、段階が逆転するため）。純粋な白は、作品や写真の色を正確に見せる必要がある場合に使う。
- 背景とグレーの色相を、アクセントの色相か暖色寄りの色相に揃える。画面全体が1つの色温度にまとまる。

## 5. 余白とレイアウト

### 5.1 外側の余白は2つの型から選ぶ

観察した実例の外側の余白は、次の2つの型に分かれ、その中間の値はなかった。コンセプトに合う型を1つ選び、ページ全体で統一する。

| 型 | 合う場面 | 作り方 |
|---|---|---|
| 端まで使う型 | 写真や大きな文字の迫力を見せたい、雑誌の誌面のような密度を出したい | 外側の余白を狭くし、4列前後のグリッドを画面の端近くまで広げる |
| 額に入れる型 | 作品を1点ずつ見せたい、静かに読ませたい | 内容の幅を狭く固定し、左右に大きな余白を取る |

- どちらの型でも、余白の値はトークンとして定義する。数値は調整欄の表に従う。

### 5.2 グリッドと配置

- 列数は、端まで使う型では PC 幅で4列前後、額に入れる型では1〜3列にする。スマートフォン幅では1〜2列にする。
- グリッドに沿いつつ、主役の要素だけ大きさや上下の位置をずらして、等間隔の格子に見えないようにする（`../design-core/references/anti-patterns.md` の X3、X9）。ずらすのは主役に限り、ほかの要素はグリッドに揃える。
- 最初の画面は、画面の高さいっぱい（100vh 前後）を1つの主役に使ってよい。中央寄せの見出しとボタン2つだけで構成しない（同 X4）。

### 5.3 余白の段階

- セクション間の余白は、項目同士の間隔の2倍以上にする（`../design-core/references/anti-patterns.md` の X9）。数値は調整欄の表に従う。
- 最初の画面では、名前や見出しのあと、最初の内容が始まるまでに大きな余白を取ってよい。余白そのものが「間」として印象を作る。

## 6. 動き

ライブラリの使い分けと具体的な書き方は、`references/motion-web.md` に従う。サイト系では次の点を守る。

- 動きの所要時間を、短い変化（ホバーでの色や不透明度の変化）と、登場や移動の2段に分ける。両者の中間の値を増やさない。
- 所要時間とイージングの既定値を1組決めてトークンにし、サイト全体で共用する。例外は用途別に2〜3組までにする。手触りが揃い、どこを動かしても同じサイトに見える。
- 登場には強い減速のカーブを、画面の大きな移動や遷移には加減速の強いカーブを使う。数値は調整欄の表に従う。
- 帯状に流れ続ける動き（文字が横に流れ続ける帯など）は、一定の速さで動くことに意味があるため `linear` を使ってよい。`../design-core/references/anti-patterns.md` の X13 の「理由」に当たるので、報告にその旨を書く。
- 演出を付ける場所は記憶のフックと主役に絞る（同 W2、X12）。
- 動きを減らす設定（`prefers-reduced-motion`）には必ず対応する（同 X15）。観察した実例の多くは対応していなかったが、ここは実例に合わせない。

## 7. 実例に見られても採らないこと

観察した実例の中にも、このスキルの禁止事項に当たる手法があった。実例で使われていたことは、使ってよい理由にならない。

- `transition: all`（`../design-core/references/anti-patterns.md` の X14）
- 理由のないブラウザ既定のイージング（`ease`、`linear`、`ease-in-out`。同 X13）
- 定番フォントを主役にした組版（同 X5）
- 動きを減らす設定への未対応（同 X15）
- スマートフォン幅に対応しない固定幅のレイアウト

## 8. ぼかさない、ずらした影（K3）の使い方

`../design-core/references/anti-patterns.md` の K3 に当たる装飾である。ぼかしのない色の影を右下にずらすと、印刷物の版ずれのような図形になり、手作りの印象が出る。サイト系で、ラベル、バッジ、ボタン、画像のどれかに使う。

- ぼかしは 0、ずらしは右下へ 4〜8px にする。色はアクセントか `text-strong` にする。
- 1ページで1つの形（ずらしの量と色）に揃え、付ける場所も1〜2種類の要素に絞る。あちこちに付けると、記憶のフックではなく模様になる。
- 浮いていることを示すためには使わない。メニューやダイアログの影は `--shadow-float` のままにする。
- トークンは `references/tokens-tailwind.md` の `--shadow-offset` を使う。

```tsx
// 黒い面のラベルに、アクセントの色の影を右下へずらして付ける
export function IssueLabel() {
  return (
    <span className="inline-block bg-text-strong px-3 py-1 font-body text-sm font-semibold tracking-[0.08em] text-surface-0 uppercase shadow-offset">
      ここにラベル
    </span>
  );
}
```

- 影は角丸のない形に付けると版ずれらしく見える。角丸を付ける場合は `rounded-sm` までにする。
- ボタンに付ける場合、押下中は `data-pressed:translate-x-[6px] data-pressed:translate-y-[6px] data-pressed:shadow-none` のように、影の位置へ押し込む動きにしてよい。移動量は `--shadow-offset-value` のずらしの量（定義例では 6px）と同じにし、ボタンがちょうど影の上に収まるようにする。

## 9. ページの多いサイトのフッター（任意の型）

組織や会社のサイトで、利用規約、プライバシーポリシー、各種の方針など、本文以外のページが多い場合に使える型である。必須ではない。

- 左に、ロゴと1行の説明を置く。
- 右に、リンクの列を並べる。各列の上に、小さな列の見出し（大文字だけの欧文なら字間を広げた小さな文字。本文の書体で組み、等幅にしない）を置く。列は「サービス」「会社」「規約と方針」のように、利用者が探す単位で分ける。
- SNS へのリンクは、Iconify のアイコン＋アカウント名の組にする。アイコンだけにしない。
- 最下段に、著作権の表記と「ページ上部へ」のリンクを置く。「ページ上部へ」の印にはアイコンを使い、文字の矢印を使わない（`../design-core/references/anti-patterns.md` の X10）。
- フッターのリンクに、外部リンクの印（↗ やそのアイコン）を付けない。フッターの列は一覧として読まれるため、印が並ぶと騒がしく、リンクの名前が読みにくくなる。
- 文字は `text-muted` を基本にし、ホバーで `text` に上げる。区切りは上端の 1px の線（`line`）だけにする。

理由：ページが多いサイトでは、利用者は規約やお問い合わせを探しにフッターへ来る。左に「これは何の組織か」、右に「探す単位で分けたリンク」を置くと、探す場所が一目で分かる。

使わない場合：ページが少ないサイト（ポートフォリオ、1ページの LP、小さな店のサイト）では、この型にしない。リンクの列が1〜2行しかないと、空の列が目立ち、大きな会社のサイトの形だけを借りたように見える。その場合は、名前、連絡先、著作権を1〜2行で置く。

## スキル作者の調整欄

以下は初期値である。実例4件の観察から、複数のサイトにまたがる幅として取り出した。スキル作者が実例を見ながら調整する。ユーザーの調整欄（`../design-core/SKILL.md` の2節） とプロンプトの指示が優先される。

値を変えるときは、`references/observations/site.md` に新しい実例の観察を足し、2件以上の実例にまたがる幅として書き直す。1つの実例の値をそのまま入れない。

### 文字

| 項目 | 初期値 | 根拠にした実例 |
|---|---|---|
| 最大の文字 ÷ 本文 | 4〜9倍 | サイト1、3、4（約 3.6〜9倍） |
| 最大の文字の大きさ（PC 幅） | 画面幅の 4〜14%（`clamp()` で伸縮） | サイト1、3、4 |
| 巨大な太字の見出しの字間 | 0〜-0.04em（大きく太いほど詰める） | サイト1（0em）、サイト4（-0.023〜-0.036em） |
| 大きな欧文見出しを複数行にする場合の行間 | 0.85〜1.0 | サイト4（0.81〜0.90）、サイト3（英字の大見出し 1.0〜1.2） |
| 中くらいの欧文見出しの字間 | +0.03〜+0.10em（大文字だけの語は範囲の上側） | サイト1（0.03em）、サイト3（0.10em） |
| 書体の数 | 2〜3書体（`../design-core/references/typography-ja.md` の上限の範囲内） | 4件とも2〜3書体 |

### 色

| 項目 | 初期値 | 根拠にした実例 |
|---|---|---|
| UI のアクセントの数 | 0〜1色 | 4件とも |
| アクセントの彩度（サイト系での上書き。`../design-core/references/color.md` の6節の条件をすべて満たす場合だけ。満たさなければ同ファイルの 0.10〜0.18） | 0.19〜0.23 まで | サイト1、3、4（0.195〜0.226） |
| ダークの背景（`surface-0`） | 明度 0.16〜0.18 | サイト1、4（明度 0.178） |

ライトの背景は `../design-core/references/color.md` の調整欄の値（`surface-0` の明度 0.985）を基本にする。次の「オフホワイトの段階」は、紙のような温度を出したい場合に使える選択肢（サイト系での上書き）であり、使う場合はライトの列をすべて差し替える。

#### オフホワイトの段階（ライトのみ、選択肢）

彩度は 0.006〜0.010、色相は暖色寄り（60〜90度）かアクセントの色相に揃える。根拠はサイト3、4（背景の明度 0.950〜0.965、彩度 0.009〜0.010）。表にない役割（`text`、`text-strong`）と、ダークの値は `../design-core/references/color.md` のままにする。

| 役割 | ライトの明度 | 確認したコントラスト |
|---|---|---|
| `surface-0` | 0.955 | — |
| `surface-1` | 0.935 | — |
| `surface-2` | 0.91 | — |
| `surface-3` | 0.885 | — |
| `line` | 0.85 | 装飾（3:1 の対象外） |
| `line-strong` | 0.76 | 装飾（3:1 の対象外） |
| `line-control`、`text-faint` | 0.58 | `surface-0` に対して約 3.8:1、`surface-2` に対して約 3.3:1 |
| `text-muted` | 0.46 | `surface-3` に対しても約 4.9:1 |

コントラストは無彩色として明度から求めた概算である。彩度を持たせた値で実装したら、媒体別スキルの検証で実測する。

### 余白とレイアウト

| 項目 | 初期値 | 根拠にした実例 |
|---|---|---|
| 外側の余白・端まで使う型（PC 幅） | 16〜48px | サイト1（約 30〜50px）、サイト4（17px） |
| 外側の余白・額に入れる型（PC 幅） | 画面幅の 8〜19% | サイト2（18.75%）、サイト3（8.3%） |
| 外側の余白（スマートフォン幅） | 14〜32px | サイト3（31px）、サイト4（14px） |
| 列数（PC 幅） | 端まで使う型は4列前後、額に入れる型は1〜3列 | サイト2（1列）、サイト3（3列）、サイト4（4列） |
| 列の間隔（PC 幅） | 16〜64px | サイト3（約 64px）、サイト4（16.7px） |
| セクション間の余白（PC 幅） | 96〜128px。ただし項目同士の間隔の2倍以上を優先し、間隔を 64px にしたら 128px にする（モデルの知識による初期値。観察で取れたのはサイト3の 112px の1件だけで、幅はこの値を中心に広げた） | サイト3（112px） |
| 項目同士の間隔（PC 幅） | 48〜64px | サイト2（48px）、サイト3（約 64px） |

スマートフォン幅のセクション間の余白は、複数の実例から値を取れなかったため初期値を置かない。PC 幅の値から縮める場合も、項目同士の間隔の2倍以上を保つ。

### 動き

| 項目 | 初期値 | 根拠にした実例 |
|---|---|---|
| 短い変化の所要時間 | 100〜300ms | サイト1、2、3、4（0.1〜0.3s） |
| 登場・移動の所要時間 | 600〜1200ms（`references/motion-web.md` の調整欄の初期値に合わせる） | サイト1（0.8s 中心、最長 1.6s）、サイト4（0.75s）。サイト3（0.5〜0.7s）は下限より短い |
