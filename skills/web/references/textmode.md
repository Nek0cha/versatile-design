# 画像の ASCII 化・網点化と覗き窓

手順4で、記憶のフックが「画像を文字や網点に崩す」「解像度を段階的に落とす」「崩れた画像の一部だけを元に戻して覗かせる」のどれかである場合に読む。それ以外の画面では、画像を文字や網点にしない。飾りとして全面に敷くと、画像も文字も読めない面になる。

## 1. 作り方の選び方

| 作り方 | 向いている場合 | 避ける場合 |
|---|---|---|
| Canvas 2D でブラウザ上で変換する（既定） | 段ごと・タイルごとに解像度が決まっている。写真を差し替えるだけで反映したい | カーソルの位置に合わせて解像度を連続的に変えたい |
| WebGL のシェーダーで毎フレーム変換する（`references/webgl.md`） | 解像度や文字の大きさを、カーソルやスクロールに合わせて連続的に変える | 変換する画像が多い（タイルごとにキャンバスと文脈が要る） |
| ビルド時に文字や画像へ変換しておく | 変換結果が固定で、表示の速さを最優先する | 画面幅に合わせて文字数を変える必要がある |

- 迷ったら Canvas 2D にする。段階的な表現（段ごとに解像度が違う）では、連続的に変えられる WebGL の強みが活きない。
- 1つの画面で、文字への崩しと網点への崩しの両方を使う場合は、崩れの順番（元の画像 → 網点 → 文字）を画面の軸（上から下、中心から外など）に沿わせる。順番のない混在は、ただの模様に見える。

## 2. 純粋関数に分ける

変換は、DOM に触れない純粋関数と、それを描く薄い部品に分ける。純粋関数には単体テストを付ける。

```ts
// 元画像（srcW×srcH）の中央から、比率 aspect（幅/高さ）の範囲を切り出す。引き伸ばさない
export function coverCrop(srcW: number, srcH: number, aspect: number) {
  if (srcW / srcH > aspect) {
    const sw = srcH * aspect;
    return { sx: (srcW - sw) / 2, sy: 0, sw, sh: srcH };
  }
  const sh = srcW / aspect;
  return { sx: 0, sy: (srcH - sh) / 2, sw: srcW, sh };
}

// 明るい順の文字。右ほど暗い（密度が高い）
export const RAMP = ' .:-=+*#%@';

// 4×4 のベイヤー行列を 0〜1 のしきい値にしたもの
export const BAYER4 = [0, 8, 2, 10, 12, 4, 14, 6, 3, 11, 1, 9, 15, 7, 13, 5].map((v) => (v + 0.5) / 16);
```

- 輝度は `0.299R + 0.587G + 0.114B` で求め、最小を 0、最大を 1 に伸ばす（正規化）。空や霧のように明暗の幅が狭い写真でも、文字と点の濃淡が出る。全部同じ値なら 0 で埋め、0 で割らない。
- 文字は `RAMP[Math.min(9, Math.floor(v * 10))]` で選ぶ。`v` は、明るい地に暗い文字なら `1 - 輝度`、暗い地に明るい文字なら `輝度` とする。
- 網点は、`v > BAYER4[(y % 4) * 4 + (x % 4)]` のセルに点を打つ。点は半径をセルの 0.36 倍の円にすると、隣と離れて網点に見える。
- テストで押さえる値：黒は `@`、白は空白。50% の灰色は 16 セル中 8 セルに点。横長の 700×393 を正方形で切ると左右が 153.5 ずつ削られる。0×0 は空文字を返し、例外を出さない。

## 3. 描く部品の決まり

- 枠の大きさは `ResizeObserver` で取り、変わるたびに文字数とセル数を計算し直す。幅か高さが 0 のときは描かない。
- 文字数は `cols = floor(幅 / (文字の大きさ × 0.6))`、`rows = floor(高さ / 文字の大きさ)` とする。等幅フォントの文字の幅は高さの約 0.6 倍のため、同じ数で割ると縦に引き伸ばされる。`line-height` は文字の大きさと同じにする。
- 輝度は、元の画像を `coverCrop` で切り出してから `cols × rows` の Canvas に縮めて読む（`getImageData`）。
- 網点の Canvas は `devicePixelRatio` 倍の解像度で描き、点は1つのパスにまとめて一度に塗る。
- 文字の `<pre>` と網点の `<canvas>` には `aria-hidden="true"` を付ける。同じ枠に、`alt` 付きの元の `<img>` を必ず重ねて置く（覗き窓の中身にも使う）。
- 画像を読み込めないときと読み込み中は、枠に背景色を敷いて場所を確保する（`../design-core/references/anti-patterns.md` の X23〜X26）。
- 3px 未満の文字は、ブラウザの最小フォントサイズの設定で拡大されることがある。読ませない装飾の段（極小の自画像など）に限って使う。

## 4. 覗き窓（レンズ）

崩れた画像の上を、窓の形のレンズが動き、レンズの中だけ元の画像が見える仕掛けである。

### 4.1 仕組み

- 各枠の元の `<img>` を、窓の形の SVG を `mask-image` にして切り抜く。`mask-size` はレンズの寸法、`mask-position` はレンズの位置から計算する。
- レンズの中心のページ座標を `<html>` の CSS 変数（`--lens-x`、`--lens-y`）に、各枠の左上のページ座標を枠自身の CSS 変数（`--tile-x`、`--tile-y`）に書く。`mask-position` は `calc(var(--lens-x) - var(--tile-x) - レンズの幅の半分)` とする。レンズが動くたびに書き換えるのは2つの変数だけで、部品を描き直さない。
- 枠の位置は、枠の大きさが変わったときに加えて、上にある要素の高さが変わったとき（`document.body` の `ResizeObserver`）と、ウィンドウの大きさが変わったときにも書き直す。
- レンズを動かす前は、変数の既定値を画面の外（`-9999px`）にして、元の画像が見えないようにする。マスクの変数（`--lens-mask`）は、最初の描画の前に設定する。設定前は `mask-image` が無効になり、元の画像が一瞬全面に見える。
- `-webkit-mask-*` も併記する。

### 4.2 落とし穴

| 起きること | 原因 | 直し方 |
|---|---|---|
| 画面の端でレンズが文書の外にはみ出し、横スクロールが出る | レンズの枠を `position: absolute` にしてページ座標で動かしている | 枠は `position: fixed` にして、画面座標（`clientX`、`clientY`）で動かす。CSS 変数には画面座標にスクロール量を足したページ座標を書く |
| ホイールでスクロールすると、レンズの中身がカーソルの位置からずれる | `pointermove` しか聞いていない | `scroll` イベントでも、最後の画面座標にスクロール量を足して変数を書き直す |
| スマートフォンで指をなぞってもレンズが付いてこない | ドラッグがブラウザのスクロールになり、`pointercancel` のあと `pointermove` が止まる | `touchmove`（`passive: true`）でも位置を更新する。スクロールは止めない |
| ばねで追従させると、レンズの枠とマスクの位置がずれる | 枠とマスクを別の値で動かしている | ばねの現在値を、枠の `transform` とマスクの変数の両方に同じフレームで書く |

- `prefers-reduced-motion: reduce` のときは、ばねを使わずにポインターの位置へ即座に移す。
- レンズの枠は `pointer-events: none` にし、下の作品をクリックできるようにする。

## 5. 確かめること

- PC 幅で、各段にレンズを当てて、レンズの中に元の画像が見えること。ホイールでスクロールしてもレンズの中身がずれないこと。
- スマートフォン幅で、画面の右端と下端をタップしても横スクロールが出ないこと（`document.documentElement.scrollWidth` が画面幅と同じ）。
- 縦長・横長・正方形の写真が、どの段でも引き伸ばされていないこと。
- 画像の読み込みに失敗した枠が、背景色の枠として残ること。
