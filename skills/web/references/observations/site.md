# サイト系の観察記録

スキル作者が選んだサイト系の実例14件を計測し、数値と原則を記録したものである。`references/mode-site.md` の数値の幅は、この記録から複数のサイトにまたがる傾向として取り出している。

このファイルは根拠の記録であり、作業の手本ではない。特定のサイトの見た目を再現するために使わない。デザインの判断には `references/mode-site.md` を使う。

## 観察の方法

- 観察日：サイト1〜4は 2026-10-03、サイト5〜14は 2026-10-06
- 各サイトのトップページを、PC 幅（1440×900px）とスマートフォン幅（390×844px）のブラウザで開き、最後まで少しずつスクロールして遅延読み込みを発火させてから計測した。
- 計測した値：計算後のスタイル（`getComputedStyle`）による書体・文字サイズ・太さ・字間・行間・色・余白・グリッド、スタイルシートの規則と CSS ファイルに書かれた `transition` と `animation` の所要時間とイージング、読み込まれたスクリプトに含まれるライブラリ名。サイト5以降は、WebGL の canvas の数と大きさ、GSAP のプラグイン、ピン留めの数、書体の配信元も計測した。
- サイト5以降は、ヘッドレスのブラウザ（ソフトウェアの WebGL）で計測した。ページ全体を WebGL で描くサイトでは、DOM から文字の値を取れないため「取得できず」とし、スクリーンショットから読み取れる構造だけを記録した。
- 字間と行間は、文字サイズに対する比（em、倍率）に換算して記載する。色は `oklch()` の明度・彩度・色相に換算した値を併記する。
- 実物の文章・画像・コードは記録しない。数値と、その数値から読み取った原則だけを自分の言葉で記載する。
- 取得できなかった値は「取得できず」と書き、推測で埋めない。

## サイト1（個人のポートフォリオ、横に流れる作品一覧）

### 観察した数値

| 項目 | 値 |
|---|---|
| 構成 | 縦のスクロール操作を横方向の移動に変換し、作品を1列に横へ並べる。縦に積むセクションはない |
| 書体 | 幾何学的なサンセリフ（Objective、通常と太字の2つのファイル）と、セリフ体（Spectral）の2系統3書体。和文は端末のゴシック体に任せる |
| 最大の文字 | 約 199px（PC 幅の約 13.8%）、字間 0、行間 1.2。画面の右端からはみ出す長さで置く |
| 作品名の見出し | 57.6px、太さ 700、字間 0.03em |
| 作品の補足 | セリフ体 22px、太さ 400 |
| 本文 | 取得できず（長い文章がない） |
| 文字の太さ | 400 と 700 の2つ |
| 色 | 背景 rgb(17,17,17)（`oklch(0.178 0 0)`）、文字は白、アクセントは赤 1色（`oklch(0.675 0.213 25)`）。アクセントはロゴの円だけに使う。進捗の線に 25% の白 |
| 左右の余白 | 固定表示のロゴとメニューは画面の端から約 30〜50px。進捗の線は左右 288px（各 20%） |
| グリッド | なし。作品の画像と作品名を上下にずらしながら横に並べる |
| セクション間の余白 | 取得できず（縦のセクションがない） |
| スマートフォン幅 | 最大の文字 62.4px、作品名 33.2px |
| 動きの所要時間 | CSS で最も多いのは 0.8s。範囲は 0.2〜1.6s。帯状に流れ続ける動きに 30s と 80s |
| イージング | `cubic-bezier(0.76, 0.07, 0.24, 0.96)`（強い加減速）、`cubic-bezier(0.215, 0.61, 0.355, 1)`（減速）、`cubic-bezier(0.19, 1, 0.22, 1)`（強い減速）の3種が中心。ほかに `ease`、`ease-in-out`、`linear` も混在する |
| ライブラリ | jQuery、GSAP の旧版（TweenMax）、画像を傾ける演出のプラグイン |
| 動きを減らす設定への対応 | CSS 上は 0件 |

### 言語化した原則

1. 画面に収まらない大きさの文字を最初の画面に1つだけ置き、はみ出させることで迫力を出す。ほかの要素は小さくして画面の四隅に寄せる。
2. 黒に近い背景と白い文字だけで組み、色はロゴの小さな円の赤1点に絞る。面積は小さいが、画面で唯一の色なので記憶に残る。
3. 太いサンセリフを作品名に、セリフ体を補足に使い、書体の切り替えで役割の差を示す。
4. 作品を等間隔の格子に収めず、上下の位置と大きさをずらして並べ、移動に緩急を感じさせる。
5. 動きは 0.8s 前後を基準にし、用途に応じてカーブを3種類使い分ける。

### 採らない点

- `transition: all` と、ブラウザ既定のイージングの混在（`../design-core/references/anti-patterns.md` の X13、X14）。
- 動きを減らす設定への未対応（同 X15）。

### 観察した数値

| 見出し | ロゴと肩書きは画像（480×174px）で、書体の実測は取得できず。読み込まれた欧文フォントは幾何学的なサンセリフ（Azo Sans）の 200・300・700、和文はゴシック体（A-OTF Gothic BBB） |

| グリッド | 1列 |
| 作品同士の間隔 | 48px（作品の画像は 900×420px） |
| 最初の画面の余白 | ロゴの下端から最初の作品まで約 230px |
| スマートフォン幅 | 幅 900px のまま縮まない（画面幅に合わせた組み替えがない） |
| 動きの所要時間 | 0.2s（ホバーで不透明度を変えるだけ） |
| イージング | `linear` |
| スクロールの演出 | なし |
| ライブラリ | jQuery と、そのイージングのプラグイン |
| 動きを減らす設定への対応 | CSS 上は 0件 |

### 言語化した原則

1. UI を白と黒だけで組み、色を作品にだけ持たせる。作品が主役のサイトでは、UI の色は作品の色と競合する。
2. 内容の幅を狭く固定し、左右に大きな余白を取ることで、作品を額に入れたように見せる。
3. 小さい文字は字間を広げ（0.12em）、行間を 2.0 にして、軽く静かな印象にする。
4. 最初の画面には名前と肩書きだけを置き、作品が始まるまでの余白で間を作る。
5. 動きをほとんど使わず、静けさそのものを印象にする。

### 採らない点

- スマートフォン幅に対応しない固定幅のレイアウト。
- `linear` のイージング（`../design-core/references/anti-patterns.md` の X13）。

## サイト3（フリーランスの事業サイト、和文が中心）

### 観察した数値

| 項目 | 値 |
|---|---|
| 書体 | Inter と Noto Sans JP の2書体（どちらも可変ウェイト） |
| 和文の主見出し | 54.4px、太さ 500、字間ほぼ 0、行間 1.25 |
| 英字の大見出し | 41.6〜51.2px、太さ 500、字間 0.10em、行間 1.0〜1.2。大文字だけで組み、隣に和文の小さな訳語を添える |
| 小見出し | 15.2〜20.8px、太さ 500〜700 |
| 本文 | 14.4〜17.1px、太さ 400、字間 約 0.015em、行間 1.6〜2.1。段落の幅は多くが 238〜394px |
| 小さいラベル | 11.2〜14.4px、字間 0.05em |
| 文字の太さ | 500 が最も多く、次に 400、700 |
| 色 | 背景は暖かみのあるオフホワイト（`oklch(0.950 0.010 82)`）、一段濃い面（`oklch(0.929 0.010 82)`）、文字（`oklch(0.187 0 0)`）、補足の文字のグレー（`oklch(0.587 0.008 89)`）、アクセントは黄 1色（`oklch(0.967 0.195 109)`）。CSS の変数に赤も定義されているが、使われている場所は取得できず |
| アクセントの使い方 | 見出しの背後の帯（蛍光ペンで引いたような面）、問い合わせの区画の背景の面、背景の手描きの線 |
| 線 | 4px の黒い太枠（18か所）と 1px の線 |
| 主要なボタン | 黒い面に明るい文字の反転を1つだけ置く |
| 左右の余白 | PC 幅で左右 120px（各 8.3%）、内容の幅 1200px。スマートフォン幅で左右 31px |
| グリッド | 3列（列の左端の位置と段落の幅から求めると、列の幅 約 357px、列の間 約 64px） |
| セクション間の余白 | PC 幅で 112px、スマートフォン幅で 80〜112px |
| 動きの所要時間 | ホバーでの色の変化は 0.2s が最も多い。要素の登場（移動と不透明度）は 0.5〜0.7s。ほかに 1s |
| イージング | ほぼすべてがブラウザ既定の `ease` |
| ライブラリ | jQuery、Swiper。スクロールでの登場は IntersectionObserver で判定 |
| 動きを減らす設定への対応 | CSS に7件の規則がある |

### 言語化した原則

1. 黄色1色に「ここが大事」という意味だけを持たせ、見出しの背後の帯と問い合わせの面に使う。色の意味がサイト全体で一貫している。
2. 黒は文字、太い枠線、主要なボタン1つの反転にだけ使い、強弱を明暗で作る。
3. 英字の大文字見出し（字間を広げる）と和文の小さな訳語を対にして、見出しの形を全体で統一する。
4. 和文の本文は行間を 1.6〜2.1 と広く取り、段落の幅を短めに保つ。
5. 背景に手描きの線を1本大きく置き、それを記憶のフックにする。ほかの部分は格子に沿って整然と組む。

### 採らない点

- Inter と Noto Sans JP の組み合わせを主役にすること（`../design-core/references/anti-patterns.md` の X5、`../design-core/references/typography-ja.md` の「主役にしない書体」）。このサイトから取り出す原則は字間と大文字の扱いであり、書体の選択ではない。
- ブラウザ既定の `ease` を全体に使うこと（同 X13）。

| 文字の太さ | 400 が最も多く、ほかに 600、700、800 |

| セクション | 多くが画面の高さ（100vh）で、セクション同士は余白なしで隣接する。CSS の変数にセクションの内側の余白の定義があり、計算後の列の間隔から換算すると約 80px になるが、どの要素に使われているかは取得できず。セクション間の余白は取得できず。明るい区画と暗い区画の境目を曲線にしている |

### 言語化した原則

1. 動きの所要時間とイージングを1組の既定値として変数にし、ほぼすべての動きで共用する。サイト全体の手触りが揃う。
2. 巨大な大文字の見出しは、行間を 1 未満にし、字間をマイナスに詰めて、文字を1つの塊として見せる。
3. 背景・文字・グレーの色相をアクセントの色相（緑〜黄緑）に揃え、彩度の強いライム1色を小さな面積で使う。
4. 画面の端まで使う4列のグリッドと狭い外側の余白で、写真を大小・上下にずらして散らし、雑誌の誌面のような密度を作る。
5. 1つの見出しの中でサンセリフとセリフ体を切り替え、書体の対比そのものを見せ場にする。

### 採らない点

- 動きを減らす設定への CSS 上の対応がないこと（`../design-core/references/anti-patterns.md` の X15）。

## サイト5（個人のブログ兼ポートフォリオ、和文が中心）

| 項目 | 値 |

| 書体 | 有料の配信サービスから読み込む幾何学的なサンセリフ（300〜700）とネオグロテスクと和文のゴシック体の3書体 |
| 最大の文字 | 160px（PC 幅の約 11%）、太さ 400、字間 0.15em、行間 1.0 |
| 和文の大見出し | 72px、太さ 400、字間 0.10em、行間 1.0 |
| 英字の見出し | 48px、太さ 700、字間ほぼ 0 |
| 本文 | 14px、太さ 400、字間 約 0.026em、行間 1.43 |
| 色 | 背景はわずかに赤みのオフホワイト（`oklch(0.966 0.002 17)`）、文字は青みの灰（`oklch(0.446 0.037 257)`）、アクセントはピンク1色（帯の写真、タグの枠、リンク） |
| WebGL | canvas は検出されず。帯は立方体を並べた 3D の画像に、点と線でつないだ網の装飾を重ねたもの |
| スマートフォン幅 | 最大の文字 96px |
| 動きの所要時間 | 0.3s と 0.15s が多い。ほかに 0.2s、1.5s |

### 言語化した原則

1. 和文の大見出しは太さ 400 のまま字間を 0.10em 広げ、太さではなく大きさと余白で主役にする。

3. セクションの見出しに、アイコンと大文字の小さなラベルを組にして置き、一覧の区切りを示す。

### 採らない点

- スクロールすると、背景のない固定のヘッダーが本文の上に重なって読めなくなる。
- 点と線でつないだ網の装飾（`../design-core/references/anti-patterns.md` の X22）。
- ブラウザ既定に近いイージングの多用（同 X13）。

| 項目 | 値 |

| 構成 | 黒い画面の左下で数字が増える読み込みの演出のあと、画面に固定した WebGL の canvas 1枚の上に HTML を重ねる。作品の 3D の場面を角丸の枠に収めて見せる |

| 最大の文字 | 144px（PC 幅の 10%）、太さ 400、字間 -0.02em、行間 1.0。文字を1字ずつ要素に分割している（約 600 個） |

| 色 | 背景は青みのオフホワイト（`oklch(0.960 0.012 281)`）と黒、アクセントは彩度の強い青1色（`oklch(0.480 0.287 266)`）。変数には緑、赤、紫も定義されているが、最初の画面では使われていない |

| 動きの所要時間 | 0.3〜0.5s |
| イージング | `cubic-bezier(0.4, 0, 0.1, 1)`、`cubic-bezier(0.35, 0, 0, 1)`（どちらも強い減速）、`ease` |
| ライブラリ | three（GSAP は検出されず） |
| 書体の配信元 | 自前配信（有料と OFL） |

### 言語化した原則

1. WebGL の canvas を画面に固定して1枚だけ置き、HTML の文字と操作をその上に重ねる。3D は1つの場面に集め、ページの各所に散らさない。

3. 背景・文字・アクセントを青の色相にそろえ、彩度の強い青1色を記憶の色にする。

### 採らない点

- 読み込みの数字の演出は、実際の読み込みと対応しているかを外から確かめられない。`references/motion-web.md` の「ページの読み込みの演出」の決まりに従う。
- 動きを減らす設定への CSS 上の対応がないこと（`../design-core/references/anti-patterns.md` の X15）。

### 傾向

1〜10 はサイト1〜4から取り出し、サイト5〜14で確かめた結果を各項目の末尾に添えた。11 以降はサイト5〜14から取り出した。

1. **アクセントは0〜1色である。** 4件とも UI のアクセントは1色以下で、使う場所は「一点」（ロゴ、主要なボタン、小さな印）か、意味を持たせた「帯や面」に限られる。アクセントを持つ3件は、いずれも彩度が 0.19〜0.23 と強い。 サイト5〜14では、色を取得できた8件中7件が UI のアクセントを0〜1色にしている。残る1件（サイト13）は、最初の画面だけに多色のグラデーションを使う。
2. **純粋な白と黒を避ける傾向がある。** 4件中3件は、背景をわずかに色相を持つオフホワイト（明度 0.95〜0.97、彩度 0.009〜0.010）か黒に近い暗色（明度 0.178）にしている。純粋な白を使う1件は、作品の色を正確に見せるためである。
3. **グレーと背景の色相を揃える。** 色相が取れた2件では、背景・グレー・アクセントの色相が近い範囲にまとまっている（暖色寄りの黄、黄緑）。
4. **見出しと本文のサイズ差が大きい。** 最大の文字は本文の約 3.6〜9倍で、最大の文字は PC 幅の約 4〜14% の大きさになる。 サイト5〜14で本文と比べられた2件では、最大の文字が本文の約 11倍（サイト5）と約 12倍（サイト8）で、PC 幅の 11〜15% だった。
5. **大きな英字見出しの字間は、大きさと太さで方向が分かれる。** 巨大な太字は字間を詰め（-0.02〜-0.04em）、行間を 1 未満にして塊にする。中くらいの大文字見出しやラベルは字間を広げる（+0.05〜+0.12em）。
6. **書体は2〜3書体に絞り、役割で分ける。** 4件中2件は、サンセリフとセリフ体を組み合わせ、見出しと補足、あるいは1つの見出しの中で切り替えている。
7. **外側の余白は両極に分かれる。** 画面の端まで使う型（PC 幅で約 17〜50px）と、額に入れたように内側に寄せる型（PC 幅で 8〜19%）に分かれ、4件の中にその中間の値はなかった。
8. **余白にメリハリがある。** セクション間の余白を取得できたサイト3では、セクション間（112px）が項目同士の間隔（約 64px）の約2倍ある。サイト2の作品同士の間隔は 48px である。セクション間の余白を数値で比べられたのは1件だけである。
9. **動きは2つの速さを持つ。** ホバーでの変化など短い動きは 0.1〜0.3s、要素の登場や移動は 0.5〜1.0s 前後で、登場や移動の演出を持つ3件はすべてこの2段に分かれる。独自のイージングを持つ2件は、どちらも強い減速の `cubic-bezier(0.19, 1, 0.22, 1)` を使い、移動には強い加減速のカーブを使う。 サイト5〜14でも、所要時間を取得できた8件は、短い変化が 0.15〜0.4s、登場や移動が 0.6〜1.2s に収まった。強い減速のカーブ（`cubic-bezier(0.19, 1, 0.22, 1)` とその近く）を中心にするサイトが4件（サイト6、9、11、13）あった。
10. **記憶のフックは1つだけである。** 各サイトは、はみ出す文字と横への移動、作品だけの1列と大きな余白、手描きの線と黄色の帯、背景の線画と散らした写真、のように見せ場を1つに絞り、ほかの部分は整然と組んでいる。

11. **WebGL は「固定した1枚の canvas」で使う。** サイト5〜14の10件中6件が WebGL を使っていた。使い方は2つに分かれる。画面に固定した canvas を1枚だけ置き、その上に HTML の文字と操作を重ねる型が4件（サイト6、9、11、12）、ページ全体を canvas で描く型が2件（サイト7、10）である。後者は文字を DOM から取得できず、対応しない環境では内容の代わりにメッセージだけが出た（サイト10）。
12. **3D は文字の背後に回す。** 固定の canvas の4件では、3D の物体をぼかすか、霧や暗さに沈めて、見出しや入口の文字の背後に置いていた（サイト6、9、11、12）。文字と 3D が同じ明るさで競合する例はなかった。
13. **GSAP は ScrollTrigger を中心に使う。** 10件中6件が GSAP を読み込み、その6件すべてが ScrollTrigger を使っていた。CustomEase は3件。ピン留め（`.pin-spacer`）は計測の時点で0件、横スクロールと Flip も0件だった。見られた型は、流れ続ける帯（サイト8はスクロールの向きに反応、サイト13は 60s の一定の速さ）、入口と読み込みの演出（サイト6の数字の増える読み込み、サイト9と12の音声を選ぶ入口）、文字の1字ずつの分割（サイト6）である。画像の切り抜きでの登場は、計測の方法では判定できなかった。
14. **見出しの書体は Google Fonts の外から来る。** 10件中9件が、見出しの書体を Google Fonts 以外（自前配信の有料・独自の書体8件、有料の配信サービス1件）から読み込んでいた。Google Fonts だけで組んでいたのは1件（サイト12）、Fontshare は0件、OFL の書体は1件（サイト6の等幅）だけだった。
15. **書体も太さも少ない。** 10件中3件が1書体か1つの太さだけで組み（サイト6、8、14）、大見出しの太さは 350〜450 が5件（サイト5、6、8、9、14）と最も多かった。太い書体で押すより、細めの書体を大きく置いて字間を詰める組み方が多い（サイト6、13、14 で -0.02〜-0.05em）。
16. **動きを減らす設定への CSS 上の対応は少ない。** サイト5〜14では10件中2件（サイト5、14）だけだった。このスキルでは実例に合わせない（`references/mode-site.md` の6節）。
