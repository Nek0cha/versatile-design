# アプリ系の観察記録

スキル作者が提供したアプリ6件のスクリーンショットを分析し、原則を記録したものである。`references/mode-app.md` の原則は、この記録から複数のアプリにまたがる傾向として取り出している。

このファイルは根拠の記録であり、作業の手本ではない。特定のアプリの見た目を再現するために使わない。デザインの判断には `references/mode-app.md` と `references/intuitive-ui.md` を使う。

## 観察の方法

- 観察日：2026-10-03（6件とも同じ日）
- 対象：スキル作者が提供したスクリーンショット。各アプリの代表的な画面である。
- スクリーンショットからは計算後のスタイルを取れないため、記録は配色の使い方、区切り方、文字の階層、操作のヒントの出し方など、画面から読み取れる構造と原則に限る。px やミリ秒などの数値は計測していない。`references/mode-app.md` の調整欄の数値は、この観察で取り出した原則に合わせてモデルの知識から置いた初期値であり、その旨を各行に書いてある。
- スクリーンショットには個人名やメッセージが含まれていたため、画像と文章は保存していない。分析結果だけを自分の言葉で記載する。

## 各アプリの観察

| 実例 | 主な観察 |
|---|---|
| アプリA（ゲームのランチャー） | アクセントの緑を、主要な操作・選択中・ON 状態・ダウンロードにだけ使い、残りはグレーの段階で組む。一覧の各行は「名前（太字・明るい）＋補足（細字・グレー）」の2段 |
| アプリB（開発者向けダッシュボード） | 黒背景の中で主要ボタンだけを白地に黒文字にし、色を足さずに主役を示す。カードは影ではなく 1px の枠線と背景の明度差で区切る。検索欄にショートカットキーを表示する |
| アプリC（オンラインホワイトボード） | キャンバスの上に浮くツールバーにだけ影と大きめの角丸を付ける。影を「浮いている」という意味を伝えるために使う |
| アプリD（チャット） | 情報量が多くても、太さと色の差で階層を作るため散らからない。見出しに件数を付ける。行ごとの操作はホバー時のみ表示する |
| アプリE（AI チャット） | 純粋な黒ではなく、わずかに暖かみのある黒の背景。あいさつの見出しにのみセリフ体を使う。アクセントカラーはロゴマークのみに使う。お知らせに閉じるボタンとその場でできる操作をセットで置く |
| アプリF（モーショングラフィックス制作ツール） | 数値パラメータの1行を「アイコン＋ラベル＋スライダー＋数値入力＋単位＋リセット」で統一する。数値表示は等幅フォント。UI の色（シアン＝選択中）と中身の色（トラックの種類）を分ける。パネルを角丸の島として浮かせ、隙間で区切る。セクション見出しを「点＋字間を広げた大文字」で統一する |

### 各アプリから言語化した原則

- **アプリA**：アクセントの意味を「押せる・選ばれている・動いている」に限定すると、色を見ただけで状態が読める。2段の行は、名前を拾い読みしながら補足を必要なときだけ読めるため、一覧が長くても疲れない。
- **アプリB**：暗い画面で最も明るい面は1つしかないため、反転したボタンは色を使わなくても主役になる。枠線と明度差だけで区切ると、影のにじみがなく、道具らしい精密さが出る。
- **アプリC**：中身（キャンバス）の上に重なる操作部品だけに影を付けると、影が「これは中身ではなく、上に浮いた道具である」という意味を持つ。
- **アプリD**：文字のサイズの段階を増やさず、太さとグレーの段階で階層を作る。操作をホバー時だけ出すことで、情報の多い画面でも、読んでいる間は操作の部品が目に入らない。
- **アプリE**：背景の黒にわずかな暖かみを持たせ、会話や長時間の利用に向いた落ち着きを出す。書体の切り替え（セリフ体）を1か所だけに使い、それを画面の印象の核にする。お知らせは「閉じる」だけで終わらせず、その場で済む操作を添える。
- **アプリF**：セクション見出しの点は区切りの印であり、状態を示す印ではない。見出しの文字も等幅フォントではない（`../design-core/references/anti-patterns.md` の X17、X18）。同じ種類の行の構成を完全に揃えると、パラメータが何十個あっても目が迷わない。数値は等幅にすると、値が変わっても桁の位置が動かない。UI の色と中身の色を分けると、選択中の表示と中身の分類が混ざらない。パネルを隙間で区切る「島」は、線を引かずにまとまりを示せる。

### 採らない点、注意する点

- アプリE のように、アクセントをロゴの印だけに使う方法は、`../design-core/references/color.md` の1節（アクセントを使ってよい3つの場所）の外にある。このスキルでは、アクセントを絞る方向として「選択中と肯定的な状態だけに使い、主要な操作は明暗の反転で示す」（同2節）を採る。ロゴの印に色を付ける場合は、それが記憶のフックであることを報告に書く。
- アプリF の UI の色と中身の色の分離は、`../design-core/references/anti-patterns.md` の K2 に当たる。同ファイルの条件と `../design-core/references/color.md` の3節の作り方に従う場合に限って使う。

## 6アプリに共通する原則

1. アクセントカラーは1色に絞り、使う場所を限定する。
2. 色を足さず、明暗の反転で主役を示す方法がある。
3. 影は浮いているものにだけ使う。
4. 文字の階層はサイズより太さと色で作る。
5. 操作のヒント（ショートカットキー、件数）を画面に出す。
6. アイコンとラベルは原則セットにする。アイコン単独は意味が定番化した場所に限る。

| 原則 | 見られた実例 |
|---|---|
| 1. アクセントは1色、場所を限定 | アプリA、E、F |
| 2. 明暗の反転で主役を示す | アプリB |
| 3. 影は浮いているものだけ | アプリB（影を使わず枠線と明度差）、C（浮くツールバーだけに影）、F（島） |
| 4. 階層は太さと色 | アプリA（2段の行）、D |
| 5. 操作のヒントを出す | アプリB（ショートカットキー）、D（件数） |
| 6. アイコンとラベルの組 | 個別の観察欄には挙げていない。6件の画面全体から取り出した傾向 |
