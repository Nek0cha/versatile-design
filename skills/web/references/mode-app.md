# アプリ系の原則と数値

コンセプトでアプリ系（ダッシュボード、ツール、設定画面、管理画面、チャットなど）と判定した画面で、トークンを決める段階で読む。実装の段階では、あわせて `references/intuitive-ui.md` を読む。具体的な数値は末尾の「スキル作者の調整欄」にまとめてある。

- このファイルは、`../design-core/references/color.md` と `../design-core/references/typography-ja.md` の原則に、アプリ系で特に効く判断を足すものである。両者と重なる数値はそちらに従う。例外は、調整欄の表で「アプリ系での上書き」と明記した行だけであり、その行に書いた条件を満たす場合に限ってアプリ系の値を使う。条件を満たさなければ、両者の値に戻る。現時点で「アプリ系での上書き」の行はない。
- `../design-core/references/anti-patterns.md` の禁止事項は、このファイルより優先する。実例で見られた手法でも、禁止事項に当たるものは使わない。
- 原則は、スキル作者が提供したアプリ6件のスクリーンショットの観察（`references/observations/app.md`）から取り出した。スクリーンショットからは数値を計測できないため、調整欄の数値はモデルの知識による初期値である。特定のアプリを再現するための値ではない。

## 1. アプリ系の目的

- アプリ系の目的は、迷わず操作できることと、毎日使っても疲れないことである。印象は、この2つを満たしたうえで作る。
- 見せ場は、部品の作り込み、状態の伝え方、情報の密度の3つである。サイト系のように大きな文字や演出で印象を作らない。
- 記憶のフック（`../design-core/references/concept-brief.md` の1節）は、最もよく使う画面の中に1つだけ置く。例：反転した主要ボタンの形、空状態の見出しだけに使うセリフ体、数値入力の増減ボタンの手触り、読み込み画面。フック以外の部分は静かに組む。

## 2. 部品は自前で作り込む

アプリ系の質は、何度も触る小さな部品で決まる。ブラウザ標準や既製 UI ライブラリの見た目をそのまま使わない。

- 部品の土台は React Aria Components とし、見た目はすべて自前のトークン（Tailwind v4 の `@theme`）で作る。shadcn/ui の既定の見た目は使わない。トークンの書き方は `references/tokens-tailwind.md` に従う。
- 特に作り込む部品と、そのレシピ（web スキルの references/components/ にある）：
  - 選択欄（select.md）：開閉の動き、選択中の印、キーボード操作、長い一覧での検索欄。
  - 数値入力（number-field.md）：ブラウザ標準の矢印を消し、自前の増減ボタンを付ける。長押しで連続して増減する。単位を添え、数字は等幅にする。
  - スクロールバー（scrollbar.md）：細く、トークンの色で、ホバー時だけ濃くする。
  - 読み込み（loading.md）：0.3秒未満の処理では何も表示しない。それより長い処理には、スケルトンか進捗の表示を出す。スピナー単独で済ませない。アプリの起動時の読み込み画面も、記憶のフックの候補として作り込む。
  - アイコン（icons.md）：Iconify の SVG を使い、ホバーや状態の変化で小さく動くアイコンを要所に使う。
- 部品の状態（ホバー、押下、フォーカス、選択中、無効、読み込み中、エラー）は、すべての部品で揃えて定義する。詳しくは states.md に従う。

## 3. 情報の密度

### 3.1 行の高さを用途で分ける

アプリ系は情報の多い画面が多い。行の高さを用途ごとに決め、同じ用途の行はすべて同じ高さにする。

| 用途 | 行の高さ | 例 |
|---|---|---|
| 密な表、プロパティの一覧 | 36px | 数値の多い表、インスペクタのパラメータ行、メニューの項目 |
| 標準の一覧 | 40〜44px | サイドバーのナビゲーション、設定の項目、1段の一覧 |
| 2段の一覧 | 52〜56px | 「名前＋補足」の2段の行、チャットの会話一覧 |

- 1つの画面で使う行の高さは2種類までにする。種類が多いと、どれが同じ種類の情報か読めなくなる。
- スマートフォン幅では、押せる行の高さを 44px 以上にする（`../design-core/references/critique.md` の C9）。36px の行は、PC 幅でマウスを使う画面だけに使う。
- 行の左右の内側の余白は、行の高さに関係なく画面全体で揃える。

### 3.2 一覧は2段で読ませる

- 一覧の各行は「主（`text-strong`、太字）＋補足（`text-muted`、細字）」の2段にする。補足は1行に収め、はみ出す分は省略記号で切る。
- サイズの差は 1〜2px に留め、階層は太さとグレーの段階で作る（`../design-core/references/critique.md` の C7）。
- 補足には、日付、件数、状態、所有者など、行を開かずに判断できる情報を置く。説明文を置かない。

### 3.3 余白の段階

- 余白は 4px を単位にした段階をトークンにする。まとまりの中は狭く（4〜8px）、まとまり同士は広く（16〜32px）し、区切りの間隔をまとまりの中の間隔の2倍以上にする（`../design-core/references/anti-patterns.md` の X9）。
- 密度を上げたいときは、文字を小さくする前に、まとまりの中の余白を詰める。本文の文字サイズは `../design-core/references/typography-ja.md` の調整欄（アプリ系 14〜15px）より小さくしない。

## 4. 色

色の作り方は `../design-core/references/color.md` に従う。アプリ系では次の点を加える。

- アクセントは1色にし、使う場所を「主要な操作、選択中、肯定的な状態（ON、完了、ダウンロード中など）」に限る（同1節）。アイコン、見出し、飾りの線には使わない。毎日見る画面では、アクセントの場所が少ないほど、色を見ただけで状態が読めるようになる。
- 大胆なアクセント（彩度の高い1色）は、面積を極小にして使う。スキル作者の好みは「強い1色を、ごく少なく」である。彩度は `../design-core/references/color.md` の調整欄の範囲に収める。
- 主要な操作は、色を足さずに明暗の反転で示す方法を先に検討する（同2節）。ダークの画面では、最も明るい面のボタンが1つだけあれば、それが主役になる。反転した面は1つの領域に1つまでにする。
- 背景の黒は、長時間使う画面、会話する画面では暖かみのある黒を、精密さを出したい開発者向けの道具では純粋な黒を選ぶ（同4節）。
- 中身を種類で見分ける必要がある場合（トラックの種類、ラベル、グラフの系列など）に限り、UI の色とは別に中身の色を定義する（同3節、`../design-core/references/anti-patterns.md` の K2）。中身が選択されたときは、中身の色を変えずにアクセントの枠線で示す。

## 5. 文字

- 書体は `../design-core/references/typography-ja.md` の組から選ぶ。印象を決めきれない場合の組（P1）を使う前に、コンセプトの印象に合う組がほかにないかを先に探す。スキル作者の好みは、定番から外れた書体である。
- 数値（表の値、パラメータ、時刻、件数、ファイルサイズ）は等幅で表示する。組の「数字」の列にある等幅書体を使うか、`font-variant-numeric: tabular-nums` を指定する（`../design-core/references/typography-ja.md` の1節の5）。値が変わったときに桁の位置が動かず、縦に並んだ値の比較もしやすい。
- 書体の切り替え（例：セリフ体）を使う場合は、空状態のあいさつや画面の題名など1か所に限り、そこを記憶のフックにする。操作の部品には使わない。
- パネルやインスペクタのセクション見出しは、「小さな印（点など）＋字間を広げた小さな文字」のように1つの形に揃える。大文字だけの欧文の字間と最小の文字サイズ（12px）は `../design-core/references/typography-ja.md` に従う。
- この点はセクションの区切りを示す印であり、状態を示す印ではない。色はグレー（`text-muted` など）にし、状態の色を付けない（状態の点は `../design-core/references/anti-patterns.md` の X18）。見出しの文字は本文の書体（`font-body`）で組み、等幅フォントにしない（同 X17）。

## 6. 面の区切りと影

### 6.1 パネルの区切り方は3つの型から1つ選ぶ

| 型 | 作り方 | 合う場面 |
|---|---|---|
| 枠線 | 1px の線（`line`）で面を区切る。面の色は背景と同じか1段違い | 純粋な黒の背景、精密さを出したい道具、表の多い画面 |
| 明度差 | 線を引かず、パネルの面（`surface-1`）と背景（`surface-0`）の明度差だけで区切る | 暖かみのある黒の背景、会話や読む時間の長い画面 |
| 島 | 角丸のパネルを背景の上に浮かせ、パネル同士の隙間で区切る | パネルの多い制作ツール、キャンバスを囲む画面 |

- 1つの画面では1つの型に統一する。枠線と島を混ぜると、どれが同じ階層の面か読めなくなる。
- どの型でも、区切りに影を使わない。数値は調整欄の表に従う。

### 6.2 影は浮いているものだけ

- 影を付けるのは、他の面の上に重なって浮いているものだけにする。例：キャンバスの上のツールバー、メニュー、ポップオーバー、ダイアログ、ドラッグ中の要素、トースト。
- 高さを表す影は浮いているもの専用の1種類（トークン --shadow-float）だけにし、浮いているものすべてに同じ影を使う。段階を増やさない。ほかに使ってよい影は、装飾としてのぼかさない、ずらした影（`../design-core/references/anti-patterns.md` の K3、トークン --shadow-offset）だけだが、これは主にサイト系のためのものであり、アプリ系の画面では使わないのを基本にする。高さの表現には決して使わない。
- 浮いているものには、影と一緒に、大きめの角丸と1段明るい面（`surface-2`）を付ける。ダークでは影がほとんど見えないため、1px の線も足す（`../design-core/references/color.md` の5節）。
- ダイアログや浮いたツールバーのように、メニューより強く浮いていることを示したい場合は、影を強くせず、角丸を大きくし（調整欄の表）、面を `surface-2` にして 1px の線を付けることで区別する。

## 7. 操作のヒントを画面に出す

- **ショートカットキー**：検索欄、主要なボタンのツールチップ、メニューの項目の右端に、キーを小さな枠付きの文字で表示する。修飾キーの表記は、利用者の OS を判定して、その OS の表記（⌘ などの記号か、Ctrl などの文字）に切り替える。矢印キーは文字の矢印ではなく Iconify のアイコンで表す（`../design-core/references/anti-patterns.md` の X10）。
- **件数**：一覧やセクションの見出し、タブ、ナビゲーションの項目の横に、中身の件数を `text-muted` の等幅数字で付ける。未読など注意を引く件数だけ、強い文字の色か小さな印で示す。0件のときは件数を消すか、薄く表示する。
- **現在の状態**：同期した時刻、保存の状態など、利用者が時々確かめたい情報は、対象のそばに控えめに常に表示する。ダイアログで知らせない（`references/intuitive-ui.md` の2節）。接続の状態のように、ほとんどの時間が正常なものは、正常な間は表示しないか、画面に1つだけの控えめな要約（最終同期の時刻など）にし、切断や遅延が起きたときだけアイコン＋文字で目立たせる（`../design-core/references/anti-patterns.md` の X20）。
- **正常な状態は静かにする**：一覧の各行やカードに「稼働中」「ONLINE」のような正常な状態のラベルを付けない（`../design-core/references/anti-patterns.md` の X20）。全体が正常であることは、見出しの横の「すべて正常」のような要約1つで伝える。異常な行（停止、警告、遅延）だけを、Iconify のアイコン＋文字で示し、状態の色はそのアイコンと文字に付ける。「● 稼働中」のような色の点＋状態の文字は使わない（同 X18）。状態をデータの印そのもの（応答時間の棒の色など）に持たせる方法もある。

## 8. ホバー時だけ現れる操作

情報の多い一覧では、行ごとの操作（編集、削除、その他のメニュー）をホバー時だけ表示し、読んでいる間は操作の部品を隠す。

- 現れる操作は、行の右端の決まった位置に置く。現れても行の高さや文字の位置が動かないよう、場所を最初から確保しておく。
- 表示の切り替えは不透明度だけで行い、所要時間は調整欄の「短い変化」の値にする。
- キーボードで行にフォーカスしたとき（`:focus-within`）にも表示する。
- ホバーできない端末（`@media (hover: none)`）では常に表示するか、行の「その他」メニュー1つにまとめる。
- 削除など戻せない操作は、ホバーで現れる場所に直接置かず、「その他」メニューの中に入れる（`references/intuitive-ui.md` の7節）。

## 9. 数値パラメータの1行

設定やインスペクタで数値を調整する行は、すべて次の構成に揃える。

アイコン ＋ ラベル ＋ スライダー ＋ 数値入力 ＋ 単位 ＋ リセット

- 列の幅を CSS グリッドで固定し、行が何十個並んでもスライダーと数値入力の位置が縦に揃うようにする。幅は調整欄の表に従う。
- アイコンはラベルと組にし、アイコンだけで意味を伝えようとしない（`../design-core/SKILL.md` の6節の6）。
- スライダーは値の幅が広い場合の大まかな調整に、数値入力は正確な値の入力に使う。両者は常に同じ値を示す。スライダーの最小値は左端に置く。
- 数値入力は自前の増減ボタンを持ち、数字は等幅で右寄せにする。単位は数値入力の中か直後に `text-muted` で置き、入力する値と区別する。作り方は web スキルの number-field.md に従う。
- リセットは、値が初期値と違うときだけ押せる状態にする。初期値のときは薄く表示するか隠し、隠す場合も場所は確保しておく。
- スライダーをドラッグする間の細かな変化は、取り消しの単位として1回にまとめる（`references/intuitive-ui.md` の4節）。
- 値の幅が狭い（目安として10段階以下）か、スライダーで調整する意味がない値は、スライダーを省き、数値入力だけにする。列の幅は揃えたままにする。

## 10. `user-select` のルール

アプリ系では、操作の部品を連打したりドラッグしたりしたときに、文字が選択されて青く反転するのを防ぐ。一方で、利用者がコピーしたい文字は選択できるように残す。詳しくは web スキルの components/selection.md に従う。

- `user-select: none` にするもの：ボタン、タブ、ナビゲーション、メニュー項目、アイコン、バッジ、チェックボックスやトグルのラベル、ドラッグできる要素。
- 選択できるまま残すもの：本文、見出し、記事の中身、エラーメッセージ、ID・注文番号・API キー・コード・メールアドレス、入力欄の中身。
- コピーされやすい値（ID、API キー、コードなど）の横には、コピーボタンを置く。
- `user-select: none` をページ全体や大きな領域にまとめてかけない。部品ごとにかける。

## 11. 動き

ライブラリの使い分けと具体的な書き方は、`references/motion-web.md` に従う。アプリ系では次の点を守る。

- 動きは操作への反応と状態の変化を伝えるために使い、飾りのための動きを足さない。毎日使う画面では、長い動きは待ち時間になる。
- 所要時間は 120〜240ms、要素ごとの遅延は 20〜40ms、イージングは減速のカーブ `cubic-bezier(0.22, 1, 0.36, 1)` を既定にする。数値は調整欄の表に従う。
- 押した瞬間の反応（押下中の見た目）は、押した時点で動き始め、調整欄の「短い変化」の時間で返す。処理の完了を待ってから反応させず、押しても何も変わらない時間を作らない。
- 一覧の並び替え、パネルの開閉、メニューの開閉では、要素がどこから来てどこへ行ったかが分かるように動かす。
- 動きを減らす設定（`prefers-reduced-motion`）には必ず対応する（`../design-core/references/anti-patterns.md` の X15）。

## 12. 実例に見られても採らないこと

- アクセントをロゴの印だけに使い、主要な操作・選択中・肯定的な状態のどれにも使わないこと。主要な操作は明暗の反転で示し、アクセントは選択中と肯定的な状態に残す（`references/observations/app.md` の「採らない点、注意する点」）。
- 条件を満たさない複数のアクセント（`../design-core/references/anti-patterns.md` の K2）。
