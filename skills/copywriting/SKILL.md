# copywriting

キャッチコピーと LP の本文を書く手順である。AI っぽさの主な原因は、言い回しよりも型と中身にある。どの商品にも当てはまる言葉を型に流し込むと、文法が自然でも AI っぽく見える。この手順は、素材を先に聞き出し、その商品にしか言えない事実から書くことで、それを防ぐ。

- 下の8つの手順を順に行う。references は最初にすべて読まず、各手順に書かれたファイルだけを、その手順に来たときに読む。
- パスはこのファイルのあるディレクトリ（以下「スキルのディレクトリ」）を基準にしている。
- 指示が食い違ったときは、プロンプトの指示 ＞ `user-preferences.md` ＞ 各 references の「スキル作者の調整欄」の順に従う。
- 対象はキャッチコピー、サブコピー、LP の本文（セクションの見出しと説明文）である。ボタンやフォームのラベルなどの短い文言は対象外とする。

## 手順1 読み込み

1. `user-preferences.md` を読む。見出しの下が空の項目は「好みなし」として扱う。
2. `references/taste.md` を読む。

## 手順2 聞き出す

読むファイル：`references/hearing.md`

1. 1回目の質問を1つのメッセージで出し、答えを待つ。依頼の文面ですでに分かっている項目は聞かない。
2. 答えから手順3の事実が1つも取り出せない場合に限り、追加の質問を1問だけ出す。
3. 質問は最大2回とする。追加の質問のあとは、答えが薄くても先に進む。

## 手順3 素材を整理する

答えから「この商品やサービスにしか言えない事実」を3つ書き出す。数字、モノの形、使う場面、作り手のこだわりなどである。以降の案は、必ずこの3つのどれかを根っこに持つ。素材が足りず推測で補った事実には「推測」と印を付け、手順6で利用者に伝える。

## 手順4 量産する

読むファイル：`references/angles.md`。英語の案を作る場合は `references/english.md` も読む。

1. 5つの切り口それぞれで4〜6案、合計20〜30案を作業用ファイルに書く。この段階では利用者に見せない。
2. 作業用ファイルは生成物に含めない。作業用ディレクトリ（スクラッチ領域や一時ディレクトリ）に置き、次の形で書く。

```md
## モノの事実
- 案
- 案

## 反転
- 案
```

3. 依頼が技術系やクリエイター系のサイトの場合は、5つの切り口のうち1〜2つを英語の案にする。

## 手順5 検査する

読むファイル：`references/anti-patterns.md`、`references/critique.md`

1. lint を実行する。

```sh
node <スキルのディレクトリ>/scripts/lint-copy.mjs <作業用ファイル>
```

2. 終了コード 0 は違反なし、1 は違反あり、2 は引数の誤りである。違反は `ファイル:行番号  ルール名  理由` の形で出る。違反した案は落とすか直す。抑制は、空っぽの言葉が商品名の一部である場合など、理由を1文で言える場合に限る。書き方は `<!-- copy-lint-disable-next-line <ルール名> -- <理由> -->` で、報告した行のすぐ上の行に書く。
3. 残った案に `critique.md` の項目をかける。自己批評は最大2周で止める。

## 手順6 5案を提示する

切り口ごとに1案ずつ、合計5案を次の書式で出す。

```
1. 〈キャッチ〉
   サブ：〈サブコピー〉
   狙い：〈切り口〉／〈根っこにした事実〉
```

- 推測で補った事実を根っこにした案は、狙いの行に「（推測）」と書く。
- 自己批評2周の後も残った問題があれば、5案の後に正直に書く。

## 手順7 利用者が選ぶ

選ばれた案で確定する。「2番と4番の間」のような指示があれば、その方向で手順4から作り直す。作り直しのときも質問はしない。

## 手順8 本文を書く

LP の本文を頼まれた場合に行う。読むファイル：`references/body.md`

1. 選ばれたキャッチの方向に合わせて、セクションの見出しと説明文を書く。
2. 本文を作業用ファイルに書き、手順5と同じ lint を実行して違反をゼロにする。
3. 素材にない数字や推薦文は作らず、「ここに数字」「ここに推薦文」と置く。

## web から呼ばれたとき

web スキルでページを作るときに、利用者がキャッチコピーや LP の本文を渡していない場合は、web からこのスキルが呼ばれる。そのときは次のように手順を変える。

- 手順2の聞き出しは、web の手順2（コンセプトを決める）と同じメッセージで行う。答えを受けたら、確認を待たずに進む。
- 手順6では利用者の選択を待たない。5案のうち最も推す1案に `（推し）` を付けてページに使い、残りの4案は web の最後の報告に並べて、差し替えられるようにする。
- 手順8の本文は、ページのコードに直接書く。lint は生成物のディレクトリに対して実行する（`.tsx`、`.jsx`、`.html` の文章の部分だけを検査する）。
- ボタンなどの短い文言は、web の決まり（ダミーと分かる仮の文章）に従う。
